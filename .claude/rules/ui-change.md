# UI 변경: 시안 3개를 먼저 고른다

화면의 모양, 배치, 문구 구성이 바뀌는 변경은 코드를 고치기 전에 시안 3개를 사용자에게 보여 주고 사용자가 고르게 한다.

## 순서

1. 변경할 화면의 시안 A·B·C를 만든다. 각 안은 배치, 정보 위계, 표현 방식 중 하나 이상이 서로 달라야 한다. 색이나 여백만 바꾼 변형은 한 안으로 친다.
2. Claude 내장 브라우저(`mcp__Claude_Browser__*`)로 세 안을 띄운다. 한 페이지에 A·B·C로 나란히 두거나 탭 3개로 연다. 화면 폭에 따라 달라지는 변경이면 데스크톱과 모바일 폭을 둘 다 보여 준다.
3. 각 안에 무엇이 다른지와 장단점을 한 줄씩 붙인다. 추천안이 있으면 이유와 함께 밝히되, 선택은 사용자가 한다.
4. 사용자가 고르기 전에는 실제 코드를 바꾸지 않는다. 여러 안을 섞으라고 하면 섞은 안을 다시 띄워 확인받는다.
5. 고른 안으로 구현하고, CLAUDE.md의 UI 변경 규칙대로 실제 브라우저에서 검증한다.

## 시안 파일

- 시안은 커밋하지 않는다. 세션 scratchpad의 독립 HTML이나 로컬 개발 서버의 임시 화면으로 만들고, 고른 뒤 지운다.

## 적용하지 않는 경우

- 오탈자나 문구 한 줄처럼 화면 구성이 그대로인 수정
- 동작만 바뀌고 화면은 그대로인 수정
- 사용자가 이미 시안(Figma 링크, 이미지, 정확한 지시)을 줬거나 시안 없이 진행하라고 한 경우

## 브리프·클라우드 세션

내장 브라우저가 없거나 사용자가 자리에 없다. 브리프에 화면 방향이 정해져 있으면 브리프를 따른다. 정해져 있지 않으면 구현하지 않고 `[ask SON-n]`으로 묻고 그 일감만 멈춘다(`.agents/plan.md` 폰 채널 규약).
