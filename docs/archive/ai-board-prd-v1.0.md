- **작성일:** 2026-11-02 (인터뷰 3라운드 결과로 확정)

## 1. 한 줄 정의

> **Experii AI Board**는 AI와 자율학습하는 대학생이 막힌 지점을 **캡처해 붙여넣기만 하면**, AI가 카드로 필기하고 · 모르는 곳을 이어서 설명하고 · 다음에 공부할 스텝을 추천하며 · 보드를 원터치로 깔끔하게 정리해 주는 **AI 칠판 기반 학습 앱**이다.

- **공모 분야:** 학습 (전공·문·이과 무관, AI로 공부하는 모든 대학생)
- **제품 형태:** Windows 데스크톱 앱(Electron). 친구 테스트는 각자의 ChatGPT 계정으로 로그인한다.
- **최종 비전(본선 범위 밖):** 학습을 정리에서 끝내지 않는다. 보드에 쌓인 학습 기록을 근거로 AI 면접관이 질문하고, 학생이 말로 설명하며 이해한 것과 아직 모르는 것을 확인해 다시 보드로 돌려보낸다. 이로써 두 문제를 잇는다: ① 공부가 남지 않는 문제(AI Board) ② 공부한 것이 실제 역량인지 확인하고 보여줄 방법이 없는 문제(AI 면접관).
- **표현 원칙:** 제안서와 발표에서 "역량을 측정한다"는 쓰지 않는다. AI 면접관 평가의 타당성 검증이 없기 때문이다. "말로 설명해 보며 이해도를 확인하고 약한 지점을 보드로 돌려보낸다"로 쓴다. 일반 AI 모의면접과의 차별점은 **질문의 근거가 내 보드(내가 실제로 공부한 기록)**라는 점이다.

## 2. 문제

| 항목 | 내용 |
|---|---|
| 누구 | ChatGPT 등 AI로 혼자 공부하는 대학생. 코딩·SQL부터 뉴스·자료 리서치까지 |
| 언제 | AI 설명 중 중요한 문장이나 모르는 지점을 만나는 순간 |
| 불편 ① | 필기하면 설명 흐름을 놓치고, 안 하면 나중에 후회한다 (필기·이해 이중 작업) |
| 불편 ② | 대화가 길어질수록 중요한 답이 위로 밀리고, 캡처는 폴더·카톡에 쌓이기만 한다 (흐름 소실) |
| 불편 ③ | 다음에 뭘 공부할지를 매번 스스로 정해야 하고, 정리가 안 되면 무엇을 모르는지도 안 보인다 |
| 현재 근거 | 창업자 본인(SQLD 학습)과 친구 2명의 직접 경험. **11/4까지 학생 3~5명 15분 인터뷰로 보강** (부록 B) |

**기존 방식과 한계:** AI 대화→노션 복붙(맥락 단절), 스크린샷→폴더·카톡(찾기 어려움), 손필기 병행(속도 못 따라감). 기존 도구는 일부 단계만 푼다. 가장 가까운 도구는 Heptabase(보드 카드를 AI 채팅 맥락으로 사용)이며, 카드 생성·배치는 수동이고 다음 스텝 추천이 없다. 상세 비교는 부록 C.

## 3. 핵심 가설과 검증

| # | 가설 | 지표 | 목표 `[목표]` |
|---|---|---|---|
| H1 | 캡처→붙여넣기→AI 카드화가 평소 방식(복붙·필기)보다 정리가 빠르다 | 같은 학습 자료 10분 정리 소요 시간 비교 | 평균 30% 이상 단축 |
| H2 | 보드가 쌓이면 AI의 다음 스텝 추천을 실제로 따라간다 | 추천 카드 클릭→학습 시작 비율(앱 기록) | 40% 이상 |
| H3 | 정리된 보드는 다시 쓰고 싶다 | 설문 재사용 의향(예/아니오), 만족도 5점 | 재사용 70% 이상 |

**테스트 설계:** 5~10명. 참여 조건은 **ChatGPT Plus·Pro 보유 학생**(앱 로그인 요건). 각자 같은 자료를 평소 방식과 AI Board로 한 번씩(순서 교차) 정리하고, 직후 설문 2문항을 받는다. 11/27~12/3에 진행한다.

## 4. 사용자와 시나리오

- **주 사용자:** AI로 자율학습하는 대학생. 문·이과 구분 없음.
- **시나리오 A (전공):** SQLD를 GPT와 공부하다가 JOIN 설명 화면을 캡처해 보드에 붙인다. 카드에 "모르겠어요"를 누르면 AI가 그 맥락으로 이어 설명하고, 보드를 보고 "서브쿼리가 비어 있어요"라며 다음 스텝을 추천한다.
- **시나리오 B (문과·리서치):** 사회 과목 보드에 뉴스 기사 URL을 붙이면 핵심 주장·근거가 출처 링크와 함께 카드로 정리된다. "원터치 정리"로 주제별 그룹이 만들어진다.

## 5. 화면

| 위치 | 내용 |
|---|---|
| 왼쪽 | 과목 목록(과목마다 보드 1개) |
| 가운데 | **AI 보드**: 카드 캔버스(이동·확대/축소), "원터치 정리" 버튼, URL 붙여넣기 |
| 오른쪽 | **AI 에이전트 패널**: 과목 맥락의 자율학습 대화, 답변마다 "보드에 필기" 버튼 |

기존 PRD의 듀오링고식 로드맵 칸은 **다음 스텝 추천 카드(점선)**로 흡수한다. 시안은 `.claude/rules/ui-change.md`에 따라 3개를 만들어 창업자가 고른다.

## 6. 핵심 루프

1. 과목을 고르고 AI 에이전트와 공부한다.
2. 중요하거나 모르는 부분을 캡처(Win+Shift+S)해 보드에 Ctrl+V 한다.
3. AI가 이미지를 읽고 **필기 카드**(원본 이미지 + 제목 + 요약)를 만든다.
4. 카드에 "모르겠어요"를 표시하거나 AI 답변을 "보드에 필기"하면 대화와 보드가 이어진다.
5. 보드 상태를 보고 AI가 **다음 스텝 추천 카드** 1~3개를 붙인다. 따라가거나, 새 대화로 자유롭게 이어간다.
6. "원터치 정리"로 카드를 그룹·연결·정렬한다.

## 7. 기능 요구사항

우선순위: **P0** 필수 루프, **P1** 본선 추가 2개, **P2** 이후.

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-01 | ChatGPT 로그인, 로그아웃, Plus·Pro 아님 안내 | P0 (기존 M2) | 로그인 후 앱 재시작해도 유지 |
| FR-02 | 과목 생성·선택, 과목마다 보드 1개 | P0 | 과목 전환 시 해당 보드와 대화가 복원된다 |
| FR-03 | AI 에이전트 대화(스트리밍, 로컬 저장) | P0 (기존 M2) | 앱 재시작 후에도 이어서 대화 가능 |
| FR-04 | 보드 캔버스: 카드 생성·이동·삭제·확대/축소, 자동 저장 | P0 | 카드 100장에서도 조작이 끊기지 않는다 `[확인필요]` |
| FR-05 | 이미지 붙여넣기(Ctrl+V, 드래그&드롭) → 이미지 카드 | P0 | 클립보드 이미지가 3초 안에 카드로 나타난다 |
| FR-06 | AI 이미지 해석: 글·수식·코드 인식, 제목+핵심 개념 요약 생성 | P0 | 이미지에 없는 내용은 쓰지 않는다. 인식 실패 시 원본만 두고 알린다 |
| FR-07 | "모르겠어요" 표시 → 그 카드 맥락으로 에이전트 대화 이어가기 | P0 | 표시한 카드가 대화 첫 메시지의 맥락으로 들어간다 |
| FR-08 | AI 답변의 "보드에 필기" → 요약 카드 생성(대화 출처 연결) | P0 | 한 번 클릭으로 카드가 생기고, 카드를 누르면 그 대화 지점이 열린다 |
| FR-09 | 다음 스텝 추천: 보드 분석 후 점선 추천 카드 1~3개 | P0 | 각 카드에 추천 근거 한 줄. 클릭 시 새 대화 시작 |
| FR-10 | 원터치 자동 레이아웃: AI가 그룹·관계를 JSON으로 제안, 배치는 알고리즘 | P1 | 한 번 클릭으로 정리되고, 되돌리기(Undo)가 된다 |
| FR-11 | URL 스크랩 → 요약 카드(핵심 주장·근거·출처 링크) | P1 | 원문 전체는 저장하지 않고 요약과 링크만 남긴다 |
| FR-12 | 사용 기록(검증용): 추천 클릭, 정리 소요 시간 등 이벤트를 로컬에 기록, 내보내기 | P1 | 사용자가 내용을 보고 내보내기를 직접 누른다 |
| FR-13 | 캡처에 키·개인정보가 있을 수 있다는 안내 문구, 대화 내용만 OpenAI로 전송됨을 표시 | P1 | 첫 이미지 붙여넣기 때 1회 안내 |

| FR-14 | (선택 과제) 보드 기반 구술 점검 미니 버전: 사용자가 카드 5장을 고르면 AI가 질문 3개를 던지고 답을 받아 피드백, 약한 카드는 "모르겠어요"로 되돌린다 | P2 (3주차 여유 시) | 질문은 선택한 카드 내용에서만 만든다. 점수·등급은 표시하지 않는다 |

**본선에서 하지 않는 것:** AI 면접관 전체 대화(FR-14 미니 버전 제외)·경험 카드 변환·리마인더, 앱 내 캡처 단축키, 모바일, 협업, 서버 동기화·계정, 모델 선택.

## 8. AI 설계

| 호출 | 입력 | 출력 | 원칙 |
|---|---|---|---|
| 이미지 해석 | 캡처 이미지 + 과목 | 제목, 핵심 개념 요약, 인식된 원문 | 보이는 것만. 추측 금지 |
| 학습 대화 | 대화 이력 + (선택) 카드 맥락 | 설명·예제 | 과목 맥락 유지 |
| 다음 스텝 추천 | 보드 카드 요약 목록 + "모르겠어요" 카드 | 추천 1~3개 + 근거 한 줄 | 근거 없는 추천 금지 |
| 레이아웃 제안 | 카드 요약 목록 | 그룹, 연결 관계(선후·포함·유사) JSON | 좌표는 LLM이 아니라 알고리즘이 계산 |
| URL 요약 | 본문 텍스트 | 핵심 주장, 근거, 출처 | 원문 복제 금지 |

보드 라이브러리는 MIT 계열(예: React Flow, Excalidraw)을 후보로 하고, 레이아웃 계산은 dagre·ELK 같은 결정론적 알고리즘을 쓴다 `[제안]`. 최종 선택은 1주차 첫 이틀에 프로토타입으로 정한다.

## 9. 데이터

대화·카드·보드·이미지는 사용자 PC의 SQLite와 로컬 파일에만 저장한다(기존 원칙). Experii 서버는 없다. 이미지와 대화 내용은 답을 받기 위해 OpenAI로만 전송된다. 사용 기록 내보내기는 사용자가 직접 한다.

## 10. 위험과 확인 필요 `[확인필요]`

| # | 위험 | 대응 |
|---|---|---|
| R1 | **ChatGPT 로그인 경로의 배포 제약.** 기존 TSD는 Phase A(셀프 등록)를 "창업자 PC 밖으로 배포하지 않는다"로 정했고, 사용자 본인 계정 로그인은 Phase C(OpenAI 승인 뒤)다. 친구 테스트가 이 제약과 충돌할 수 있다 | 1주차 첫날 약관·승인 상태를 다시 확인. 막히면 (a) 사용자가 자기 API 키를 입력하는 모드, (b) 창업자 PC 옆 관찰형 테스트 3~5명으로 축소 |
| R2 | **이미지 입력 가능 여부.** 기존 TSD는 `/v1/responses`와 `store:false`만 확인했고, 이 경로에서 이미지 입력이 되는지는 확인 기록이 없다 | M0 스파이크로 첫날 확인. 안 되면 로컬 OCR → 텍스트 모델 경로로 대체 |
| R3 | 테스트 참여 요건(Plus·Pro 보유)이 좁아 5~10명 모집이 어려울 수 있다 | 모집을 11/10부터 시작. 모집 기준을 설문 첫 문항으로 둔다 |
| R4 | 뉴스 스크랩의 저작권 | 요약과 출처 링크만 저장 |
| R5 | 20일 일정(3인) | 필수 P0 4개를 2주차 끝까지 완료, P1은 3주차. 못 끝내면 P1을 시연용으로 축소 |
| R6 | 자동 레이아웃 결과가 들쭉날쭉 | LLM은 그룹·관계만 제안, 배치는 알고리즘. Undo 제공 |

## 부록 A. 대학생 후킹 멘트 (공감형)

숫자가 든 문구는 인터뷰 결과가 나오면 실제 수치로 바꾼다. "합격 보장"·"1위" 같은 성과 보장·단정 표현은 쓰지 않는다(랜딩 PRD 7장 규칙).

**제안서·포스터 헤드라인 후보**
1. AI랑 몇 시간을 공부했는데, 머릿속엔 왜 아무것도 없지? ← **제안서 1번 첫 문장으로 사용**
2. 분명 AI가 알려줬는데… 그게 어디 있더라?
3. 캡처는 쌓였는데, 다시 열어본 적은 없다.
4. 필기하면 설명을 놓치고, 안 하면 시험 전날 후회한다.
5. 모르는 게 생길 때마다 대화창은 길어지고, 나는 길을 잃는다.

**한 줄 후속 문구 (Experii의 답)**
- 캡처해서 붙이면, 필기는 AI가 합니다.
- 다음에 뭘 공부할지, 보드가 알려줍니다.
- 정리는 버튼 한 번. 칠판은 AI가 닦습니다.
- 코딩 공부도, 뉴스 스크랩도 한 칠판에서.

**발표·SNS 오프닝 후보**
- "여러분, 어제 AI랑 공부한 내용 지금 말해 보세요."
- "스크린샷 폴더 열어 보세요. 다시 본 사진이 몇 장인가요?"

**추천 조합:** 헤드라인 1 + 후속 "캡처해서 붙이면, 필기는 AI가 합니다."

## 부록 B. 인터뷰 질문지 (학생 3~5명, 15분, 11/3~11/4)

**섭외 조건:** AI(ChatGPT·Claude 등)로 공부해 본 대학생. 전공이 서로 다르면 더 좋다(문·이과 확장 근거).

1. 요즘 AI로 어떤 공부를 하나요? 가장 최근 사례를 하나 말해 주세요.
2. 그때 AI 답변에서 중요하거나 모르겠던 부분을 어떻게 남겼나요? (필기·캡처·복붙·아무것도 안 함)
3. 남겨 둔 것을 나중에 다시 열어본 적이 있나요? 마지막으로 본 게 언제인가요?
4. 대화가 길어졌을 때 예전 답변을 찾아야 했던 적이 있나요? 어떻게 찾았나요?
5. "다음에 뭘 공부해야 하지?"를 어떻게 정하나요? 그때 막막했던 적이 있나요?
6. (아이디어 설명 30초 후) 이런 보드가 있다면 쓰고 싶은가요? 어떤 점이 걱정되나요?
7. 이런 도구를 쓰려면 ChatGPT 유료 플랜이 필요합니다. 쓰고 계신가요? 테스트에 참여할 수 있나요?

**기록 양식:** 이름(익명 가능) / 전공·학년 / Q2 답 / Q3 답 / 인상 깊은 한 문장(그대로 인용) / Q7 유료 플랜 여부.

**제안서 반영 방법:** "N명 중 N명이 캡처를 쌓아만 두고 다시 보지 않는다고 답했다" 형태의 수치 1개 + 인용 1~2문장을 제안서 1번 `[인터뷰 결과 입력]` 자리에 넣는다.


## 부록 C. 기존 대안 조사 (2026-11-02, 공식 문서·소개 페이지 기준)

**읽는 법:** ○ 공식 자료에서 확인됨 / △ 일부·수동 / × 읽은 자료에서 확인되지 않음(없다는 뜻이 아님). 일부 근거가 2025년 문서라 현재와 다를 수 있으니 제안서 제출 전에 Heptabase·NotebookLM 최신 기능을 한 번 더 확인한다 `[확인필요]`.

| 도구 | 보드 | AI가 보드 내용을 맥락으로 사용 | 캡처 → AI 카드 자동 생성 | AI 답변 → 보드 카드 | 자동 정리 | 다음 스텝 추천 | 학습 점검 |
|---|---|---|---|---|---|---|---|
| **Heptabase** | ○ 화이트보드+카드 | ○ 보드·카드·이미지·PDF 카드 | × (이미지는 맥락으로 사용) | △ 사용자가 드래그 또는 "New card" | × 수동 | × | × |
| **FigJam AI** | ○ | △ 스티커 정렬·요약 | × | × | △ 스티커를 주제 등으로 정렬 | × | × |
| **Miro AI** | ○ | ○ Sidekick이 캔버스 맥락을 읽음 | × | × | × (소개 페이지에서 미확인) | × | × |
| **Flowith** | ○ 노드형 캔버스 | ○ 노드 대화 분기 | × (이미지 생성 위주) | ○ 대화가 곧 노드 | × 수동 | × | × |
| **NotebookLM** | △ 마인드맵 | ○ 올린 자료 기반 | × | × | × | × | × (읽은 글 기준) |
| **ChatGPT 학습 모드** | × | - | × | × | - | × | ○ 지식 점검, 진도 추적 |
| **Gemini Guided Learning** | × | - | × | × | - | × | ○ 설명 흐름 끝 퀴즈 |
| **사람인 AI 모의면접** | - | × | - | - | - | - | ○ 이력서·공고 기반 질문, 음성, 리포트. 학습 기록과 연동 없음 |
| **Experii AI Board** | ○ | ○ | ○ | ○ 한 번 클릭 | ○ 원터치 | ○ | ○ 보드 기반(FR-14, 선택) |

**해석**
1. **가장 가까운 경쟁은 Heptabase다.** "AI 대화 + 보드"는 새롭지 않다. 차별점은 **한 번의 동작으로 이어지는 자동화**(캡처→카드, 답변→카드, 정리)와 **다음 스텝 추천**이다. 제안서에서 "보드 위 AI 채팅" 자체를 새롭다고 주장하지 않는다.
2. 학습 모드(ChatGPT·Gemini)는 **점검**이 있고 **보드**가 없다. 반대로 보드 도구는 **정리**가 있고 **점검·추천**이 없다. 두 쪽을 한 흐름으로 잇는 것이 포지션이다.
3. AI 모의면접은 **이력서·공고**에서 질문한다. Experii의 질문 근거는 **학생이 실제로 공부한 보드**다. 이 한 가지를 반드시 방어 논리로 가져간다.
4. 발표에서 "아무도 없다"고 말하지 않는다. "조사한 범위에서 이 흐름을 한 번에 잇는 도구는 확인하지 못했다"로 쓴다.

**조사 한계:** 요약 도구로 공식 페이지를 읽었고, 로그인이 필요한 최신 기능과 앱 안 기능은 못 봤다. Miro AI 페이지는 클러스터링·이미지 입력이 "언급 없음"일 뿐 없다는 확증이 아니다. 한국 AI 면접 서비스는 사람인과 앱스토어 1종만 읽었다.
