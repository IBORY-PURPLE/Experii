# Experii PRD v0.1

- **문서 목적**: 랜딩페이지 제작용 제품 요구사항 정리
- **작성일**: 2026-10-26
- **근거**: 브랜드 코어 코치 인터뷰 Q1~Q3 확정 내용 (Q4 운영 채널, Q5 운영 계획은 미완)
- **표기**: `[확인필요]` 아직 근거가 없는 항목 / `[가설]` 검증 전 가정 / `[제안]` 코치가 제안한 초안

## 1. 한 줄 정의

> 우리는 AI와 공부한 대화를 면접용 경험으로 정리해 주는 **Experii**를 만들고, AI로 SQLD 같은 자격증을 공부하며 “이게 면접에 쓸모 있을까” 막막한 **취업 준비 대학생**에게, **“자격증 있어요”밖에 못 하던 답변이 “이런 과제에서 이렇게 써 봤어요”로 바뀌는** 변화를 준다.

**포지셔닝**: 면접에 집중한 학습 애플리케이션

## 2. 핵심 가설

## 3. 문제

고객(창업자 본인과 주변 대학생)이 실제로 한 말입니다.

- “AI와 공부하며 공부 시간은 늘어났는데 이해도는 떨어지는 느낌”
- “웹 리서치로 얻은 정보가 노션과 카톡에 누적만 되어 있고 실제로 다시 보지 않음”
- “웹 리서치 시간이 너무 아까움”
- 범용 AI에 “지금까지 대화 정리해서 저장해 줘”라고 하면 쌓이기는 하지만, **다시 꺼내 주는 트리거가 없다**
- 알림 예약, MCP, 스킬 세팅은 할 수 있지만 일반 대학생에게는 귀찮고 어렵다

**정리**: 공부는 했는데 면접에서 꺼낼 경험으로 남지 않는다. 쌓아 둔 기록은 다시 보지 않는다.

> 근거는 아직 창업자 본인과 친구 2명 수준입니다. `[확인필요]` 대학생 3~5명 인터뷰로 보강이 필요합니다.

## 4. 타깃 고객

| 항목 | 내용 |
| --- | --- |
| 누구 | 개발자가 아닌 일반 대학생. Claude·GPT가 좋다는 건 알지만 제대로 활용하지 못하는 사람 |
| 상황 | AI와 대화하며 SQLD 같은 자격증을 공부하다가, “이게 자격증 따는 공부일 뿐 면접에서는 쓸모없지 않을까” 느낄 때 |
| 이유 | 면접·적성검사·AI 역량 검사는 “SQL 쓸 줄 아세요?”가 아니라 “어떤 과제에서 그 기술을 어떻게 썼나요?”를 묻는다 |
| 원하는 것 | 서류 다음 면접까지 버틸 수 있는, 내 경험으로 말할 거리 |

## 5. 가치 제안과 USP

### USP 한 문장

> 취업 준비 대학생은 AI로 서류는 쉽게 쓰지만 정성적인 대화가 오가는 **면접**에서 막히는데, TIO·자소설닷컴은 **지원 직전에** 지금까지 한 것을 긁어모아 서류를 다듬어 주지만, **면접에 집중한 학습 앱** Experii는 이미 쓰고 있는 GPT·Claude를 **추가 비용 없이** 연결해 **공부하는 날마다** 현장 과제와 경험 카드를 쌓아 줘서, 면접에서 **1년 치 내 경험**으로 대화하게 한다.

### 근거 3가지

1. 공부 대화 맥락에서 바로 현장 과제를 내고, 푼 결과를 면접 답변 한 줄로 저장한다 (제작 방식)
2. 1·7·30일 리마인드로 배운 점, 활용 방안, 면접 예시 답변을 다시 꺼내 준다 (제작 방식)
3. 이미 구독 중인 GPT·Claude를 연동해 별도 구독료가 없다 (가격·구성, 연동 가능 여부 `[확인필요]`)

후기 근거는 아직 없습니다 `[확인필요]`.

### 경쟁사가 따라 말할 수 없는 이유

TIO도 면접 준비를 하지만 지원 시점부터 시작합니다. 사용자의 몇 달 치 공부 기록은 Experii 안에만 쌓이고, 나중에 거꾸로 만들어 낼 수 없습니다. 단, **사용자가 꾸준히 써야 성립**합니다. 리텐션이 USP의 전제 조건입니다.

## 6. 제품 개요

### 제품 형태

- 모바일 **애플리케이션** (단순 웹사이트가 아님)
- 사용자가 이미 구독 중인 GPT·Claude를 앱에 연동 (참고: 구독 AI를 브라우저에 연결하는 ASIDE 방식)
- 사용자는 Experii 앱 안에서 AI와 학습 대화를 하고, 그 대화 맥락으로 경험 카드가 만들어진다
- 학습이 경험으로 바뀌는 과정을 **시각적이고 인터랙티브하게** 보여준다

### 핵심 루프

1. **학습 대화**: 앱 안에서 GPT·Claude와 SQLD 공부
2. **현장 과제**: 배운 내용을 실제 업무 상황 과제로 적용
3. **경험 카드 저장**: 푼 경험을 면접 답변 한 줄로 저장
4. **리마인드**: 공부 후 1일·7일·30일에 앱 알림으로 다시 꺼내 체화

### 기능 요구사항 (MVP 후보)

| ID | 기능 | 설명 | 연결 키워드 |
| --- | --- | --- | --- |
| F1 | AI 구독 연동 | 가입 후 기존 GPT·Claude 구독을 연결. 세팅 3분 이내 목표 | 귀찮지 않은 |
| F2 | 학습 대화 | 앱 안에서 자격증 공부 대화. 첫 과목은 SQLD | 공부가 경험으로 남는다 |
| F3 | 현장 과제 생성 | 대화 맥락에서 실무형 과제를 내고 사용자가 직접 적용 | 공부가 경험으로 남는다 |
| F4 | 경험 카드 | 푼 과제를 면접 답변 한 줄 형태로 저장. 학습에서 경험으로 바뀌는 과정을 시각화 | 공부가 경험으로 남는다 |
| F5 | 리마인드 알림 | 기본 1·7·30일. 알림 내용: 배운 점, 활용 방안, 면접 예상 질문과 예시 답변 | 쌓아 둔 걸 다시 꺼내 준다 |
| F6 | 이력서·면접 답변 생성 | 누적된 경험 카드로 이력서와 면접 답변 작성 | 공부가 경험으로 남는다 |

### 온보딩 목표 흐름

가입 → GPT·Claude 연동 → 공부 대화 시작. 세팅 3분 이내. 이후 사용자는 공부만 하면 된다.

### 쓰지 않는 표현 (광고 문구 확인 필요)

- “면접 준비 끝”, “합격 보장”, “면접에서 확연한 차이” 같은 **성과 보장** 표현은 근거 자료 없이 쓰지 않는다
- “최고”, “1위”, “유일” 같은 단정·비교 표현은 쓰지 않는다
- 경쟁사를 직접 깎아내리는 비교 문구는 쓰지 않는다

**주의**: TIO도 “범용 AI보다 취업 준비에 맞춤화”를 내세운다. 따라서 “범용 AI보다 편하다”만으로는 차별점이 되지 않는다.

### 참고 사례: bragdoc (해외)

- 소프트웨어 개발자 대상. git 커밋을 성과로 정리해 인사평가 문서를 만든다

## 9. 비즈니스 모델

- 사용자에게 **구독료를 받지 않는다**. 사용자가 이미 쓰는 GPT·Claude로 상위 모델을 쓴다
- 1단계 목표는 수익이 아니라 **사용자 유치**
- 사용자 50만 명 확보 후 학원, 학습 플랫폼, 과목별 제휴사 입점으로 **제휴 수익** `[가설]`
- 리스크: 무료는 경쟁사가 따라 하기 쉬우므로 USP가 아니라 진입 장벽 제거 수단으로 다룬다

## 10. 랜딩페이지 요구사항

### 목적

USP를 검증하고 초기 사용자를 모은다. 성공 지표는 Q5(운영 계획)에서 확정한다. `[제안]` 사전 신청 수를 1차 지표로 둔다.

### 섹션 구성 `[제안]`

| 순서 | 섹션 | 담을 내용 |
| --- | --- | --- |
| 1 | 히어로 | 한 줄 정의의 Before→After. “자격증 있어요” → “이런 과제에서 이렇게 써 봤어요” |
| 2 | 문제 | 공부 시간은 늘었는데 남는 게 없다. 노션·카톡에 쌓기만 하고 다시 안 본다 |
| 3 | 시대 변화 | 서류는 AI로 쉬워졌다. 이제 어려운 건 정성적인 대화가 오가는 면접 (H1 가설, 단정 표현 주의) |
| 4 | 작동 방식 | 핵심 루프 4단계 시각화: 학습 대화 → 현장 과제 → 경험 카드 → 1·7·30일 리마인드 |
| 5 | 차별점 | 지원 직전이 아니라 공부하는 날마다. 몇 달 치 기록은 나중에 만들 수 없다 |
| 6 | 귀찮지 않은 시작 | 가입 → 내 GPT·Claude 연동 → 3분. 추가 구독료 없음 |
| 7 | CTA | 사전 신청 (SQLD 공부 중인 대학생 우선) |

### 히어로 카피 후보 `[제안]`

1. 공부하는 오늘이, 면접에서 말할 경험이 됩니다
2. “자격증 있어요” 대신 “이렇게 써 봤어요”
3. 자격증 공부하면서 면접 답변도 같이 쌓으세요

### 서브 카피 후보 `[제안]`

- 이미 쓰는 GPT·Claude를 연결하면 3분이면 준비 끝. 이제 공부만 하세요. 면접 소재는 Experii가 쌓아 둡니다.
