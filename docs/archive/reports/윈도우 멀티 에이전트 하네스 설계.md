# 역할 에이전트를 세션으로 띄우고 탭으로 꺼내라

지금처럼 한 채팅 안에서 PM·리서치·종합 역할을 서브에이전트로 병렬 실행하는 구조로는 특정 에이전트를 맥락째 별도 탭이나 창으로 꺼낼 공식 방법이 없다. Claude Code는 서브에이전트를 세션으로 승격해 달라는 요청을 stale 처리로 not planned 종결했고, Codex는 MultiAgentV2 하위 스레드의 직접 입력을 막았으며, 벤더 중립 표준인 ACP의 서브에이전트 초안도 클라이언트가 자식 세션에 prompt·resume하는 것을 금지한다 ([#80798](https://github.com/anthropics/claude-code/issues/80798), [#33885](https://github.com/openai/codex/issues/33885), [ACP subagents RFD](https://agentclientprotocol.com/rfds/subagents)). 해법은 구조를 뒤집는 것이다. 역할마다 이름 붙은 최상위 Claude Code background 세션(`claude --bg -n research-2 "..."`)으로 띄우면 꺼내기는 `wt -w crew nt --title research-2 claude attach research-2` 한 줄이 되고, 같은 live 프로세스에 붙으므로 대화 맥락이 그대로 남으며, 다른 역할은 cross-session messaging(`@research-2`)으로 계속 연락할 수 있다 ([agent view](https://code.claude.com/docs/en/agent-view), [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)). 이 조합은 Windows 전용 수정 이력이 쌓인 문서화 기능만으로 오늘 시도할 수 있지만, 핵심 기능이 모두 research preview라 바뀔 수 있고 이 PC에서의 왕복 동작은 아직 실측하지 않았다. 커뮤니티, Lauren Tan(SpaceXAI), OpenAI, SpaceX/xAI, Anthropic 다섯 진영의 실무자는 모두 사람이 직접 말을 거는 단위를 최상위 세션으로 두고 서브에이전트는 결과만 받는 일회용으로 쓰며, 실시간으로 대화하는 세션은 한 자릿수에서 멈추고 그 이상은 PR·티켓 단위 비동기 위임으로 넘긴다. 그런데 "Windows Terminal 탭으로 한 명령 팝아웃, 꺼낸 뒤에도 팀 소속 유지, 사람이 곁에서 나눈 대화를 종합 에이전트가 반영, Claude·Codex 동급 혼합, 한국어 IME 검증"을 한데 묶은 제품은 조사한 OSS·상용·1st-party 어디에도 없다. 그러니 만들 것은 새 터미널이 아니라 벤더 CLI 세션 위에 얹는 얇은 Windows 관제층이고, 차별점은 벤더가 언제든 따라 할 수 있는 "탭 열기"보다 **사람이 특정 역할과 따로 나눈 대화를 기록하고 PM·종합 에이전트에 전달하는 곁대화 원장(side-conversation ledger)**과 주의 라우팅에 둬야 한다.

*기준일 2026-10-26. 근거는 2026-10-25~26에 작성된 리서치 노트 7건이며, "로컬"은 이 PC(Windows 11 Home 10.0.26300, Claude Code 2.1.309, Codex CLI 0.144.5)에서 직접 확인한 결과라 URL이 없다.*

## 1. 결론 요약: 구조를 뒤집으면 팝아웃은 명령 한 줄이 된다

사용자가 물은 것에 먼저 짧게 답한다. 근거는 2~6절에 있다.

| 질문 | 답 | 근거 |
|---|---|---|
| 지금 구조에서 특정 역할 에이전트에게 따로 지시할 수 있나 | 같은 화면 안에서는 된다. Claude Code 서브에이전트 패널에서 행을 골라 Enter로 transcript를 열고 입력하면 그 에이전트로 간다. 별도 탭·창으로 승격하는 공식 경로는 Claude·Codex 모두 없다 | [sub-agents](https://code.claude.com/docs/en/sub-agents), [#80798](https://github.com/anthropics/claude-code/issues/80798), [#33885](https://github.com/openai/codex/issues/33885) |
| 명령 하나로 별도 탭에 띄우는 방법이 지금 있나 | 있다. 역할을 처음부터 이름 붙은 background 세션으로 띄우고 `wt ... claude attach <이름>`을 실행한다. attach는 실행 중인 프로세스에 붙고, 떼어도 세션은 계속 돈다 | [agent view](https://code.claude.com/docs/en/agent-view), [wt CLI](https://learn.microsoft.com/en-us/windows/terminal/command-line-arguments) |
| 꺼낸 뒤에도 팀에 남나 | 남는다. background 세션은 inbox를 계속 바인딩해 이름으로 `SendMessage`를 받고, 네이티브 Windows에서는 세션별 named pipe로 전달된다. 다만 "사람이 이 역할과 따로 대화했다"는 사실을 PM·종합 에이전트가 자동으로 알지는 못한다 | [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging), [#72591](https://github.com/anthropics/claude-code/issues/72591) |
| Codex도 되나 | 설치본 0.144.5에서 검증된 경로는 "원래 TUI를 끝내고 새 탭에서 `codex resume <id>`"로 넘기는 hand-off뿐이다. 붙지 않고 지시하는 `codex queue`와 대시보드 `codex agents`는 0.149.0에서 추가됐다는 제3자 근거가 있다 | [Codex developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli), [proflead](https://proflead.dev/posts/openai-codex-agents-dashboard-codex-queue/) |
| cmux 같은 터미널을 Windows용으로 새로 만들어야 하나 | 아니다. 맥락은 Claude supervisor가, 보기는 이미 깔린 Windows Terminal이 맡는다. 하네스는 레지스트리·알림·팀 버스만 얹으면 된다. 자체 터미널은 OSC 상태 신호 해석이 꼭 필요해질 때까지 미룬다 | 4·5절 |
| 무엇으로 차별화하나 | Windows Terminal 네이티브 사후 팝아웃, 곁대화 원장, Claude·Codex 동급 팀, 훅 기반 주의 라우팅, 한국어 IME 검증 | 3·5절 |
| 가장 큰 리스크는 | research preview 변경, Anthropic 구독 OAuth 정책과 쿼터 N배 소모, Codex app-server의 실험 단계, 하네스가 고칠 수 없는 Claude Code TUI의 한국어 IME 버그, 벤더의 기능 흡수 | 5-6절 |

"구조를 뒤집는다"는 말의 뜻은 아래 표와 같다.

| | 지금 구조 | 권장 구조 |
|---|---|---|
| 역할의 정체 | 한 채팅 안의 서브에이전트(프롬프트로 정의) | 이름 붙은 최상위 세션(`claude --bg -n <role> --agent <role>`) |
| 사람이 보는 것 | 종합 에이전트의 최종 답 | 역할별 중간 산출물 파일과 관제 탭의 상태 목록 |
| 특정 역할에게 지시 | 부모에게 전달을 부탁하거나 같은 화면 패널에서 입력 | 새 탭에서 직접 대화(`hx pop`), 또는 관제 탭에서 엿보고 답하기 |
| 역할 간 연락 | 부모가 중계 | `@이름` 메시지와 팀 버스 |
| 수명 | 부모 세션에 종속, transcript는 기본 30일 뒤 삭제 | supervisor가 유지, 탭을 닫아도 계속 실행 |

이 뒤집기가 통하는 이유는 맥락을 쥔 주체가 터미널이 아니라 Claude Code의 supervisor 프로세스이기 때문이다. 탭은 창문일 뿐이라 어느 탭에서 붙든 같은 대화가 이어진다 ([agent view](https://code.claude.com/docs/en/agent-view)). 지금 습관을 버릴 필요도 없다. PM을 메인 채팅 자리에 그대로 두고 나머지 역할만 background 세션으로 내리면 된다. 대가는 쿼터다. 문서도 에이전트 10개를 병렬로 돌리면 쿼터가 대략 10배 빨리 닳는다고 적었다 ([agent view](https://code.claude.com/docs/en/agent-view)).

## 2. 다섯 진영 모두 사람과의 직접 대화는 최상위 세션으로만 한다

다섯 진영의 공개 자료를 같은 축에 놓으면 차이보다 공통점이 크다. 아래 표는 사람이 누구와 직접 대화하는지, 몇 개까지 다루는지, 특정 에이전트를 어떻게 조종하는지, 무엇으로 검증하는지를 비교한다.

| 진영 | 사람이 직접 말을 거는 단위 | 동시 운용 규모 | 특정 에이전트 조종 방식 | 검증 장치 | 하네스에 주는 시사점 |
|---|---|---|---|---|---|
| 커뮤니티 | 따로 띄운 최상위 세션(tmux 세션·pane) | 사람당 약 8개가 실용 상한이라는 의견 ([HN](https://news.ycombinator.com/item?id=47221691)) | attach/detach, 붙지 않고 큐잉 전송(agent-deck `o`·`Shift+Q`), lead 경유(Gas Town Mayor) ([agent-deck](https://github.com/asheshgoplani/agent-deck), [Gas Town](https://github.com/gastownhall/gastown)) | 사람 리뷰, merge 충돌이 병목 | attach 모델과 큐잉 전송을 tmux 없이 제공 |
| Lauren Tan (SpaceXAI) | 러너 채팅 하나 | 초기 대화 1~5개 감독, `orchestrate`는 자식 약 10개 rolling·중첩 깊이 3 ([Redreamality](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/), [pstack](https://github.com/cursor/plugins/tree/main/pstack)) | 러너에게만 지시, 서브에이전트는 매번 새로 띄우고 원래 브리프와 이후 지시를 합쳐 넘김 | verification skill, measured/inferred/guessed 라벨, 다른 모델 계열 교차 리뷰 | 팝아웃을 "재브리핑 승격"으로 구현하는 근거, 산출물 증거 라벨 |
| OpenAI | 인터랙티브 세션(창) | 엔지니어 대부분 3~5개에서 한계(Symphony 팀), Steinberger 4~10개 ([Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/), [Lex Fridman](https://lexfridman.com/peter-steinberger-transcript/)) | Esc로 멈추고 상태를 물은 뒤 재지시, Symphony는 티켓 상태로만 소통 | 에이전트끼리 리뷰(Ralph Wiggum Loop), proof of work 영상 | 주의력 관리가 제품의 중심, Codex V2는 자식 직접 입력 금지 |
| SpaceX/xAI (SpaceXAI) | Agent Dashboard의 세션 행(서브에이전트는 부모 세션 아래) | 공식 수치 없음, "엔지니어 1명당 에이전트 약 20개"는 단일 인터뷰 ([NextBigFuture](https://www.nextbigfuture.com/2026/01/inside-xai-and-future-of-millions-of-emulated-humans.html)) | 행을 골라 peek→reply, 열면 take over ([Agent Dashboard](https://x.ai/news/agent-dashboard)) | plan 승인 뒤 clean diff, Cursor 연구의 judge | 입력 대기 우선 정렬, Working/Idle/Awaiting 상태 모델 |
| Anthropic | 터미널 탭·worktree·agent view 행·데스크톱 세션 | Boris는 로컬 탭 5개 + 웹 5~10개, teams 문서는 팀원 3~5명 권장 ([Boris 스레드](https://threadreaderapp.com/thread/2007179832300581177.html), [agent teams](https://code.claude.com/docs/en/agent-teams)) | 직접 개입할 일은 별도 세션, 서브에이전트는 결과만 | 자기 검증 피드백 루프, 분리된 회의적 evaluator | 중간 산출물은 파일로, 개입 단위는 세션 |

**커뮤니티** 도구는 거의 모두 따로 띄운 최상위 세션을 관리한다. claude-squad는 tmux 세션에 `↵`/`o`로 붙고 `ctrl-q`로 떼는 모델이고, agent-deck은 붙지 않은 채 메시지를 보내되 상대가 바쁘면 인터럽트 없이 큐에 넣는다 ([claude-squad](https://github.com/smtg-ai/claude-squad), [agent-deck](https://github.com/asheshgoplani/agent-deck)). 그래서 커뮤니티의 불만은 사용자의 불만과 그대로 겹친다. 코디네이터가 띄운 에이전트에 대해 보이는 것은 그들이 보고하기로 고른 것뿐이고 대개 낙관적으로 다듬어져 있다는 HN 댓글, 기존 세션을 팀에 합류시켜 달라는 요청의 not planned 종결이 대표적이다 ([HN](https://news.ycombinator.com/item?id=47605971), [#24294](https://github.com/anthropics/claude-code/issues/24294)). 한국 개발자도 이 흐름의 한가운데 있다. 프롬프트로 역할 팀을 정의하는 oh-my-claudecode는 **4만 스타**를 넘겼지만 `omc team` 워커는 일이 끝나면 죽기 때문에 사람이 그 워커와 협업을 이어갈 수 없다 ([oh-my-claudecode](https://github.com/Yeachan-Heo/oh-my-claudecode)).

**Lauren Tan**(@poteto)은 Meta에서 React Compiler를 맡다가 2026년 봄 Cursor에 합류했고, SpaceX가 Cursor를 인수한 뒤 SpaceXAI에서 Grok Bot을 만든다 ([Redreamality](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/), [AICoder](https://aicoder.com/news/news-20260921-poteto-cursor-compile-2500-prs)). 노트는 Mads Lorentzen과 Garry Tan도 후보로 검토했지만 음차, 소속, 그리고 이 PC에 그의 pstack이 설치돼 있다는 사실이 모두 Lauren Tan을 가리켰다. 9월 토크의 핵심 명제는 **"신뢰가 먼저, 병렬은 그다음"**이다. 에이전트가 자기 일을 검증하지 못하면 검증 시스템은 여전히 사람이고, 그 상태로 에이전트를 100개 열면 쓰레기 PR 더미만 나온다 ([Redreamality](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/), [The New Stack](https://thenewstack.io/agentic-verification-distributed-systems/)). pstack에서 사람은 `/poteto-mode`를 받은 러너 채팅 하나와만 대화하고, 러너가 playbook·todo·모든 서브에이전트 생성을 소유한다. 서브에이전트는 기본적으로 매번 새로 띄우며, 원래 브리프와 이후 모든 지시, 이전 보고와 브랜치를 합친 "consolidated scope"를 넘긴다. 기존 에이전트를 resume하는 경우는 로컬 체크아웃이나 실행 중인 dev server처럼 옮기기 비싼 상태가 있을 때뿐이고, 인터럽트로 이어 붙인 resume은 지시를 조용히 잃는다고 경고한다 ([pstack](https://github.com/cursor/plugins/tree/main/pstack); 로컬 pstack 0.15.32 `skills\poteto-mode\SKILL.md`). 여러 날짜리 `orchestrate` playbook에서 코디네이터는 코드를 고치지 않고 자식 약 10개를 rolling window로 돌리며, 상태를 status.md·ledger.tsv·inbox/·gates.md 파일에 남기고, 사람은 하루 두 번쯤 들여다본다. 승인은 공유 브랜치 force-push·배포·데이터 삭제·고객 메시지처럼 되돌릴 수 없는 일에만 받는다 ([Flavio Copes](https://flaviocopes.com/poteto-mode/); 로컬 pstack `skills\poteto-mode\playbooks\orchestrate.md`). 그의 철학은 "서브에이전트와 직접 대화"의 반대편에 있지만, 새 러너가 이전 transcript와 브랜치를 넘겨받는 Session pickup처럼 벤더 내부 포맷에 기대지 않는 승격 방식을 보여 준다. 덧붙여 pstack의 Claude Code 매핑에서는 Grok 역할이 `inherit-parent`로 바뀌어 arena·interrogate의 모델 계열 다양성이 사라진다. 사용자의 Codex CLI가 그 두 번째 계열을 채울 수 있다 (로컬 pstack `docs\harness\claude-code.md`).

**OpenAI**의 공개 실무는 두 갈래다. 하네스 팀(Ryan Lopopolo, 2026-02-11)은 사람이 손으로 쓴 코드 없이 약 5개월 동안 **약 100만 줄과 머지 PR 약 1,500개**를 만들었다며 사람의 일을 환경·의도·피드백 루프 설계로 옮겼다. AGENTS.md는 약 100줄짜리 지도로 두고, 에이전트가 다른 에이전트 리뷰어들이 만족할 때까지 자기 변경을 고치는 "Ralph Wiggum Loop"를 돌린다 ([Harness engineering](https://openai.com/index/harness-engineering/)). Symphony 글은 사용자의 상황을 정확히 묘사한다. 엔지니어 대부분이 Codex 세션 **3~5개**를 넘기면 어느 세션이 무엇을 하는지 놓쳤고, 그래서 Linear 티켓 단위 위임으로 바꿨는데, 그 대가로 실행 도중 방향을 슬쩍 바로잡는 능력을 잃었다고 인정했다. 사양에도 사람이 라이브 세션에 입력을 넣는 메커니즘이 없다 ([Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/), [SPEC.md](https://github.com/openai/symphony/blob/main/SPEC.md)). 인터랙티브 쪽 대표인 Peter Steinberger(2026년 2월 합류)는 에이전트 4~10개를 창으로 나란히 띄우고 오래 걸리면 Esc로 멈춰 상태를 묻는다. 2025년 글에서는 맥락을 직접 통제하려고 리서치를 서브에이전트 대신 별도 터미널 창에서 돌린다고 했고, Gas Town식 완전 자동 오케스트레이터는 폭포수 모델에 빗대며 회의적이다 ([Lex Fridman](https://lexfridman.com/peter-steinberger-transcript/), [Just Talk To It (2025)](https://steipete.me/posts/just-talk-to-it)). 제품도 같은 쪽을 택했다. Codex는 subagent를 기본으로 켜되 스티어링은 부모를 거치게 하고, MultiAgentV2 하위 스레드는 TUI 입력과 app-server의 `turn/start`·`turn/steer`를 모두 거부한다. 이 가드는 10월 15일 main에도 남아 있었고, OpenAI 지원팀의 답은 "공유할 일정 없음"이었다 ([Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents.md), [#33885](https://github.com/openai/codex/issues/33885), [OpenAI 커뮤니티](https://community.openai.com/t/codex-regression-v2-subagents-cannot-receive-user-follow-ups/1391127)). Steinberger의 "서브에이전트 대신 창"은 사용자가 원하는 팝아웃을 손으로 구현한 셈이지만, 그 방식에서는 공유 맥락과 종합 에이전트, 곧 팀이 사라진다.

**SpaceX/xAI**에서 2026년 10월의 "SpaceX 엔지니어"는 사실상 SpaceX의 AI 조직을 가리킨다. SpaceX는 2026-02-02 xAI를 인수했고, 6월 16일 Cursor 운영사 Anysphere를 약 600억 달러에 인수한다고 발표해 8월 14일 종결했다 ([Yahoo Finance](https://finance.yahoo.com/news/elon-musks-spacex-merges-xai-153111324.html), [AP via NY1](https://ny1.com/nyc/all-boroughs/ap-top-news/2026/06/16/spacex-buys-ai-coding-startup-cursor-for-60-billion-in-race-for-an-edge-over-anthropic-and-openai), [Drive Tesla Canada](https://driveteslacanada.ca/?p=119834)). "SpaceXAI"가 공식 부서명인지는 1차 출처로 확인되지 않았고, 로켓·Starlink 엔지니어가 직접 공개한 멀티 에이전트 워크플로나 머스크의 5단계 "알고리즘"을 에이전트 작업에 적용한 문서도 찾지 못했다. 공개된 것은 제품과 연구다. Grok Build의 Agent Dashboard(2026-06-15)는 입력을 기다리는 세션을 맨 위로 올리고, 행을 고르면 대시보드를 떠나지 않은 채 최신 출력을 엿본 뒤(peek) 바로 답하게 하며, 세션을 열면 대화 전체를 넘겨받는다(take over). 상태는 Working/Idle/Awaiting 세 가지이고 행마다 현재 실행 중인 명령과 경과 시간이 붙는다 ([Agent Dashboard](https://x.ai/news/agent-dashboard)). 인수 전 Cursor 연구는 수백 개 에이전트를 planner/worker/judge로 나눴는데, 락 방식에서는 **에이전트 20개의 처리량이 2~3개 수준**으로 떨어졌고, 별도 integrator 역할은 병목이 됐으며, 표류를 막으려면 주기적으로 새로 시작해야 했다 ([Cursor Blog](https://cursor.com/blog/scaling-agents)). xAI 엔지니어가 "엔지니어 1명이 에이전트 약 20개와 프로젝트를 이끌었다"고 말한 팟캐스트는 검증되지 않은 단일 인터뷰이고, 그는 방송 나흘 뒤 회사를 떠났다 ([NextBigFuture](https://www.nextbigfuture.com/2026/01/inside-xai-and-future-of-millions-of-emulated-humans.html), [Unwire.hk](https://unwire.hk/2026/01/21/xai-engineer-ghori-podcast-departure/ai/)). 사용자 관점에서 peek→reply→take over는 "팝아웃"에 가장 가까운 공개 선례이고, Claude Code agent view도 Space(엿보기)와 Enter(붙기)로 같은 구조를 갖췄다.

**Anthropic**의 Claude Code 팀은 "직접 개입할 일은 별도 최상위 세션, 결과만 필요한 일은 서브에이전트"로 일관된다. Boris Cherny는 2026년 1월 번호 붙인 터미널 탭 5개와 claude.ai/code 세션 5~10개를 돌리며 입력 대기를 OS 알림으로 알았고, 최고의 팁으로 Claude에게 자기 일을 검증할 피드백 루프를 주면 **품질이 2~3배** 오른다는 점을 꼽았다 ([Boris 스레드](https://threadreaderapp.com/thread/2007179832300581177.html)). 팀 팁은 git worktree 3~5개에 탭마다 색과 이름을 붙이는 것이었고, 4월에는 auto mode·recap·focus mode로 "맡겨 두고 다음 Claude로 주의를 옮기는" 방식이, 5월에는 agent view와 데스크톱 다중 세션, 아침에 머지 준비된 PR을 받는 Routines가 더해졌다 ([팀 팁 스레드](https://threadreaderapp.com/thread/2017742741636321619.html), [4월 스레드](https://threadreaderapp.com/thread/2044847848035156457.html), [Simon Willison](https://simonwillison.net/2026/May/6/code-w-claude-2026/)). Nicholas Carlini의 C 컴파일러 실험은 Claude 16개를 오케스트레이터도 메시징도 없이 lock 파일과 git으로 조율했고, 사람은 실행 중 개입하지 않고 테스트와 하네스만 설계했다 ([Anthropic Engineering](https://www.anthropic.com/engineering/building-c-compiler)). 설계 원칙은 사용자의 불편을 직접 설명한다. 2025년 연구 시스템 글은 멀티 에이전트가 채팅보다 **약 15배 토큰**을 쓰고, 폭넓은 연구에는 맞지만 맥락을 공유해야 하는 코딩에는 안 맞으며, lead가 서브에이전트를 동기적으로 기다리는 구조가 조종의 병목이라고 짚었다 ([multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)). 2026년 dynamic workflows 글은 fan-out 뒤의 synthesize 단계를 모든 갈래를 기다리는 barrier로 정의한다 ([A harness for every task](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)). 사용자의 "PM → 리서치 ×N → 종합"이 바로 이 패턴이고, barrier 뒤에서 요약만 보는 구조가 "마지막 결과만 읽힌다"는 불만을 만든다. Anthropic의 처방은 서브에이전트 산출물을 파일 같은 외부 저장소에 쓰고 가벼운 참조만 넘기는 것이다.

다섯 진영을 겹치면 네 가지가 수렴한다. 사람이 직접 말을 거는 단위는 어디서나 최상위 세션이다. 실시간으로 대화하는 세션은 한 자릿수에서 멈추고, 그 이상은 PR·티켓·Routines 같은 비동기 위임으로 넘어간다. 병렬화보다 검증과 증거가 먼저다. 표준 UX는 "입력 대기 우선 정렬, 엿보고 답하기, 넘겨받기"다. 반대로 자식 에이전트를 독립 대화 세션으로 승격하는 기능을 문서화한 곳은 하나도 없다. 사용자의 지금 구조는 이 흐름을 거스르고 있어서 불편하다.

## 3. 기존 대안은 꺼내기를 자기 앱 안에 가두거나 Windows를 버렸다

아래 세 표는 사용자가 원한 방식, 곧 "이렇게 설계돼 있고, 그래서 이 점이 불편하다"로 정리했다. 실패 유형은 셋이다. spawn하는 순간에만 pane을 배정해 사후 팝아웃이 안 되거나(cmux shim, psmux), 자기 앱 안에 탭을 그려 OS 터미널로 꺼내지 못하거나(VS Code, Warp, Devin, Cursor), 아예 Windows를 지원하지 않는다(Conductor, Sculptor, Intent, cmux, WSL 전용인 OpenRig).

### 4-2. 오늘 바로 쓰는 우회 레시피

가장 강한 조합은 **역할을 이름 붙은 background 세션으로 띄우고, 관제 탭에서 상태를 보고, 꺼낼 때만 새 탭에서 attach**하는 것이다. 각 줄의 플래그는 공식 문서로 확인했지만 이 PC에서 조합해 돌려 본 적은 없다(6절 E1~E8). 경로는 예시다.

```powershell
# A. 역할을 꺼낼 수 있는 형태로 띄운다 (저장소에서 claude를 한 번 대화형으로 열어 workspace trust를 먼저 준다)
cd C:\work\repo
claude --bg -n pm         "PM: 목표를 쪼개 @research-a, @research-b에 배정하고 결과를 @synth에 넘겨라"
claude --bg -n research-a "리서치 A: ... 결과는 .crew/research-a/report.md에 쓰고 @synth에 알려라"
claude --bg -n synth      "종합: .crew/*/report.md를 읽고 주장마다 근거 라벨을 붙여 종합하라"
claude agents --json        # name, id, state, waitingFor 확인 (TTY 불필요)

# B. 관제 탭: agent view (Space=엿보고 답하기, Enter=그 자리에서 attach, Alt+1..9=바로 attach)
Start-Process wt.exe -ArgumentList '-w crew new-tab --title control -d "C:\work\repo" claude agents'

# C. 팝아웃: 관제 탭은 그대로 두고 research-a만 새 탭으로 (같은 live 프로세스)
Start-Process wt.exe -ArgumentList '-w crew new-tab --title research-a --tabColor #2E86DE -d "C:\work\repo" claude attach research-a'

# D. 나란히 보기: 현재 탭을 좌우로 나눠 synth를 붙인다
Start-Process wt.exe -ArgumentList '-w crew split-pane -V --size 0.4 --title synth claude attach synth'
```

꺼낸 탭에서 빈 프롬프트의 `←`, `/exit`, `Ctrl+Z`로 떼어도 세션은 멈추지 않는다. 이름으로 attach하는 기능은 프로세스가 살아 있을 때만 되고(v2.1.290 이상), 멈춘 세션은 id로 붙어야 한다 ([agent view](https://code.claude.com/docs/en/agent-view)). 실행 중인 background 세션에 `claude --resume <세션>`을 걸어도 attach로 처리되고, 커맨드라인에 프롬프트를 붙이면 그 세션의 다음 턴으로 먼저 전달된다(v2.1.285 이상). 그래서 새 탭에서 `claude --resume research-a "범위를 2024년 이후로 좁혀"`를 실행하면 "메시지를 들고 들어가는 팝아웃"이 된다 ([sessions](https://code.claude.com/docs/en/sessions)). PM은 지금처럼 메인 탭에서 대화형(`claude -n pm`)으로 열어 둬도 다른 세션과 메시지를 주고받을 수 있다. 탭 제목에 Claude가 쓰는 세션 이름과 상태 글리프가 보이도록 `--suppressApplicationTitle`은 쓰지 않는다.

역할끼리의 연락은 하네스 없이도 된다. PM 세션에서 "@research-a에게 범위를 좁히라고 전해"처럼 쓰면 `SendMessage`로 간다(v2.1.232 이상). 수신 세션이 작업 중이면 도구 호출 사이에 읽고 idle이면 새 턴을 시작하며, `notify_when_idle`을 쓰면 상대가 끝났을 때 한 번 통지받는다 ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)). `/fork`로 "같은 출발점의 토론방"을 만들 때는 출력된 `claude attach <id>`를 레시피 C처럼 새 탭에서 실행하면 된다.

알림은 Notification 훅과 터미널 벨을 겹쳐 쓴다. `agent-toast.ps1`은 훅 stdin에서 세션 이름과 메시지를 읽어 토스트를 띄우는 스크립트인데, 입력 필드명은 아직 확인하지 않았고 BurntToast 대신 WinRT 직접 호출이나 작은 헬퍼 exe가 필요하다. 문서 예시인 MessageBox는 터미널 창 뒤에 뜰 수 있다 ([hooks guide](https://code.claude.com/docs/en/hooks-guide)).

```json
// ~/.claude/settings.json
{
  "preferredNotifChannel": "terminal_bell",
  "hooks": {
    "Notification": [
      { "matcher": "permission_prompt|idle_prompt|agent_needs_input|agent_completed",
        "hooks": [ { "type": "command",
          "command": "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\\tools\\agent-toast.ps1" } ] }
    ]
  }
}
```


데스크톱 앱만 쓰고 싶다면 역할마다 Code 세션을 따로 만들고(Ctrl+N), Ctrl+클릭으로 새 창, Alt+클릭으로 나란히 보기를 쓴다. Claude는 데스크톱의 cross-session 도구로 다른 Code 세션을 나열·읽기·메시지할 수 있지만, 데스크톱이 직접 돌린 세션만 보이고 기본은 최근 20개다 ([desktop](https://code.claude.com/docs/en/desktop)). Codex는 hand-off로 처리한다.

```powershell
# Codex: 원래 TUI를 끝낸 뒤 새 탭에서 이어 가기 (두 프로세스 동시 resume 동작은 미검증)
Start-Process wt.exe -ArgumentList '-w crew new-tab --title codex-review -d "C:\work\repo" codex resume <SESSION_ID>'
# 0.149.0 이상으로 올린 뒤: 붙지 않고 지시 넣기 (유휴면 깨우고, 작업 중이면 다음 안전 지점에서 처리)
codex queue --thread <SESSION_ID> --message "리뷰 범위를 auth 모듈로 좁혀라"
```

Claude 팀원을 pane으로 꼭 보고 싶다면 psmux 안에서 `claude`를 실행하는 "파워 모드"가 있다. settings에 `"teammateMode": "tmux"`를 두면 Agent View를 다시 열 때 in-process로 돌아가는 문제를 피할 수 있지만, worktree 격리 에이전트는 여전히 보이지 않고 Claude Code 내부 구현에 기대므로 업데이트 때 깨질 수 있다 ([psmux docs](https://github.com/psmux/psmux/blob/HEAD/docs/claude-code.md)).

### 4-3. 레시피 전에 피해야 할 지뢰 다섯 개

첫째, 이미 포그라운드 터미널에서 돌고 있는 일반 세션을 다른 탭에서 fork 없이 `--resume`하면 두 프로세스의 메시지가 한 transcript에 섞인다. 꺼내기 전에 원래 세션을 `/bg`로 background에 넘겨야 한다 ([sessions](https://code.claude.com/docs/en/sessions)). 둘째, git 저장소의 background 세션은 편집을 시작할 때 `.claude/worktrees/` 아래 자기 worktree로 옮겨지고, **v2.1.198부터는 끝나면 묻지 않고 자기 브랜치를 commit·push하고 draft PR을 연다**. 리서치 역할이 의도치 않게 PR을 여는 일을 막으려면 `worktree.bgIsolation` 정책을 정해 둬야 한다 ([agent view](https://code.claude.com/docs/en/agent-view)). 셋째, attach되지 않은 유휴 세션은 약 1시간 뒤 프로세스가 멈췄다가 다음 attach 때 transcript에서 재시작되므로, 오래 대기시킬 역할은 `Ctrl+T`로 고정한다 ([agent view](https://code.claude.com/docs/en/agent-view)). 넷째, 데스크톱 앱은 PowerShell 프로필을 읽지 않으므로 하네스 명령을 프로필 함수로만 만들면 데스크톱 세션에서는 보이지 않는다. PATH에 둔 스크립트로 만든다 ([desktop](https://code.claude.com/docs/en/desktop)). 다섯째, Claude 세션 안의 Bash 도구(Git Bash)에서 `wt.exe`를 부르면 MSYS 경로 변환이 끼어들 수 있으니 `powershell.exe -NoProfile -Command "Start-Process wt.exe ..."`로 감싼다(미검증).

## 5. 최적 설계안: 벤더 세션 위에 얹는 얇은 Windows 관제층

### 5-1. 아키텍처: 맥락은 supervisor, 보기는 Windows Terminal, 하네스는 그 사이

설계 원칙은 다섯 줄이다. 첫째, **spawn은 하네스가 소유한다**. 팝아웃할 가능성이 있는 역할은 절대 세션 안의 서브에이전트로 만들지 않는다. Claude 모델이 팀원과 worktree 서브에이전트 중 무엇을 띄울지 스스로 고르면, Windows에서 worktree 쪽은 보이지 않는 in-process로 돌아 꺼낼 수 없다 ([psmux docs](https://github.com/psmux/psmux/blob/HEAD/docs/claude-code.md)). 둘째, 맥락은 벤더 supervisor가, 보기는 Windows Terminal이 쥐고, 하네스는 그 사이의 얇은 층에 머문다. 셋째, 세션당 writer는 하나다. 넷째, 제어와 관찰은 구조화된 표면(`claude agents --json`, hooks, `--json` 이벤트, app-server 알림)으로만 하고 화면 스크래핑과 내부 파일 파싱은 하지 않는다. 터미널 스크래핑의 대표였던 coder/agentapi는 TUI가 바뀔 때마다 파서를 고쳐야 한다고 스스로 밝히다가 2026년 9월 아카이브됐다 ([agentapi](https://github.com/coder/agentapi)). 다섯째, 팀 상태는 열린 파일 포맷으로 둔다. 이 분야는 도구 사망률이 높다.

```
[사용자]  hx CLI · /pop 슬래시 명령 · globalSummon 핫키 · 토스트
   │
   ▼
[hx 데몬 127.0.0.1]  registry(team.json) · http 훅 수신 · 곁대화 원장(ledger.jsonl) · 토스트 · 팀 버스(MCP)
   │ spawn/stop               │ 관찰                          │ 조정
   ▼                          ▼                               ▼
[Claude supervisor]        claude agents --json            SendMessage(@이름, named pipe)
  claude --bg 세션들          + 세션별 http hooks             + MCP 메일박스·보드
[Codex 세션]               Codex --json 이벤트·hooks         + .crew/<team>/<role>/report.md
  exec/resume (P2: app-server)                              + codex queue (0.149+)
   │
   ▼ 보기
[Windows Terminal -w crew]  control 탭: claude agents   /   역할 탭·분할: claude attach <id>, codex resume <id>
```

아래 표는 노트가 정리한 제어 표면을 여섯 요구로 대조한 것이다(✓ 문서화된 수단으로 가능, △ 부분·우회, ✗ 불가).

| 표면 | N개 띄우기 | 상태 스트림 | 맥락째 팝아웃 | 실행 중 지시 | 에이전트 간 연락 | 종합으로 회수 |
|---|---|---|---|---|---|---|
| 세션 내 서브에이전트(지금 방식) | ✓ 동시 20·깊이 3 | △ | ✗ | △ `SendMessage` 재개 | △ | ✓ |
| Agent teams | ✓ 대화형만 | △ | △ 같은 창 | ✓ | ✓ 메일박스 | ✓ |
| Claude background 세션 + attach | ✓ | ✓ `agents --json`, hooks | ✓ live | △ attach 입력, `SendMessage` | ✓ | ✓ |
| Claude `-p`·Agent SDK | ✓ | ✓ | △ hand-off | ✓ `streamInput` | △ | ✓ |
| Codex exec·resume | ✓ | ✓ JSONL | △ 실행 후 | ✗ 턴 단위 | △ MCP | ✓ |
| Codex app-server(실험) | ✓ | ✓ | △~✓ 이중 구독 미검증 | ✓ `turn/steer` | △ | ✓ `thread/inject_items` |
| ACP 어댑터 | ✓ | ✓ | ✗ attach 개념 없음 | △ cancel 후 재prompt | ✗ | ✓ |

근거는 [agent view](https://code.claude.com/docs/en/agent-view), [headless](https://code.claude.com/docs/en/headless), [Codex app-server](https://learn.chatgpt.com/docs/app-server), [ACP subagents RFD](https://agentclientprotocol.com/rfds/subagents)다. Claude background 세션 + attach만이 "맥락째 팝아웃"과 "팀 연결 유지"를 문서화된 수단으로 동시에 만족한다. 그래서 이것을 코어로 삼고, Codex는 hand-off 멤버로 시작해 app-server가 안정되면 live attach로 올리며, ACP는 관찰·정규화 어댑터로만 쓴다. 벤더를 섞은 조정은 세 CLI가 모두 클라이언트로 붙는 MCP 서버에 메일박스와 태스크 보드를 두는 방식이 가장 실용적이다. MCP Agent Mail이 에이전트 신원·메일박스·파일 예약을 MCP로 제공하는 선례다 ([MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail)). MCP는 에이전트가 도구를 불러야 읽는 pull 방식이므로, 즉시 전달이 필요한 Claude끼리는 `SendMessage`, Codex는 `codex queue`로 보완한다.

### 5-2. 명령 체계: 동사 열한 개와 슬래시 명령 하나

명령 이름 `hx`는 가칭이다.

| 명령 | 하는 일 | 내부 구현(문서화된 표면) | 성숙도 |
|---|---|---|---|
| `hx up <team>` | team.yaml의 역할을 이름 붙은 세션으로 일괄 실행하고 `crew` 창에 관제 탭을 연다 | Claude: `claude --bg --name <role> --agent <role> "<brief>"`, Codex: `codex exec --json "<brief>"`로 첫 턴을 돌리고 thread id 기록, 관제 탭 `claude agents --cwd <repo>` | Claude ✓, 설정 플래그 조합은 E3 |
| `hx ls` | 역할별 상태(작업 중·입력 필요·유휴·완료), 대기 이유, 곁대화 여부 | `claude agents --json --all` 폴링(`state`, `waitingFor`, `name`, `sessionId`)과 훅 이벤트 | ✓ |
| `hx pop <role> [--split] [--window] [--say "<msg>"]` | 관제 탭은 두고 대상만 새 탭·분할·창으로. `--say`는 메시지를 들고 들어간다 | Claude: `wt -w crew nt --title <role> --tabColor <c> claude attach <id>`, `--say`는 `claude --resume <id> "<msg>"`, Codex: lease 확인 후 `codex resume <id>` | Claude ✓(`--say`는 E16), Codex △ |
| `hx send <role> "<msg>"` | 붙지 않고 지시 | Codex 0.149+: `codex queue --thread <id> --message`. Claude는 비대화형 전송 CLI가 없어 PM 경유 `@role`, 팀 버스 메일박스, 관제 탭 peek 답장 중 하나. channel은 실험 | Codex ✓(업그레이드 후), Claude △ |
| `hx back <role>` | 탭을 떼고 곁대화를 원장에 확정, PM·종합에 알림 | `UserPromptSubmit`·`Stop` http 훅 → 원장, 역할의 standing order가 `@synth`·`@pm`에 요약 전송 | 설계 필요 |
| `hx log <role>`, `hx show <role>` | 붙지 않고 최근 출력, 중간 산출물 보기 | `claude logs <id>`, `.crew/<team>/<role>/report.md` | ✓ |
| `hx fork <role> [--as <name>]` | 같은 출발점의 토론방을 복제해 새 탭으로 열고 멤버로 등록 | `/fork` 또는 `claude --resume <uuid> --fork-session --bg`(조합은 E15) | △ |
| `hx adopt <subagent>` | 기존 채팅의 서브에이전트를 재브리핑으로 승격 | `SubagentStop` 훅의 `agent_transcript_path`·`last_assistant_message`와 원래 브리프로 새 named 세션을 띄움(pstack의 consolidated scope 방식) | △ |
| `hx focus <role>` | 해당 창을 앞으로 | WT `globalSummon` 핫키(사용자 시작)와 `wt -w crew focus-tab -t <i>` | △ |
| `hx down [role]` | 정지·정리 | `claude stop <id>`, `claude rm <id>`(Claude가 만든 worktree도 함께 삭제) | ✓ |

같은 동사를 Claude Code 슬래시 명령(`/pop research-2`)으로도 노출해, 사용자가 지금처럼 메인 채팅 안에서 "research-2 꺼내줘"라고 말하면 PM이 `hx pop`을 실행하게 한다. #24123에는 `/fork` 뒤의 "새 탭 열고 id 입력"을 자동화한 사용자 플러그인 `/fork-session`이 이미 소개됐다 ([#24123](https://github.com/anthropics/claude-code/issues/24123)). 팀 정의는 열린 파일 하나로 둔다.

```yaml
# team.yaml (설계안)
team: research
cwd: C:\work\repo
roles:
  pm:         { vendor: claude, agent: pm,          color: "#E67E22", isolation: none, main: true }
  research-1: { vendor: claude, agent: researcher,  color: "#2E86DE", isolation: none }
  research-2: { vendor: claude, agent: researcher,  color: "#2E86DE", isolation: none }
  reviewer:   { vendor: codex,  profile: reviewer,  color: "#27AE60" }   # 다른 모델 계열의 교차 리뷰
  synth:      { vendor: claude, agent: synthesizer, color: "#8E44AD", isolation: none }
artifacts: .crew/{team}/{role}/report.md
ledger: .crew/{team}/ledger.jsonl
```

Phase 0에서는 PATH에 둔 PowerShell 스크립트로 충분하다. 아래는 실측 전 초안이다.

```powershell
# hx-pop.ps1 (Phase 0 초안, 미검증)
param([Parameter(Mandatory)][string]$Role, [switch]$Split)
$s = claude agents --json --all | ConvertFrom-Json |
     Where-Object { $_.name -eq $Role } | Select-Object -First 1
if (-not $s) { throw "세션 '$Role' 없음: claude agents --json 확인" }
$verb = if ($Split) { 'split-pane -V --size 0.4' } else { 'new-tab' }
Start-Process wt.exe -ArgumentList "-w crew $verb --title $Role claude attach $($s.id)"
```

### 5-3. UX: 관제 탭은 그대로 두고 대상만 새 탭으로

하루를 그려 보면 이렇다. 아침에 메인 탭에서 `hx up research`를 친다. `crew`라는 Windows Terminal 창이 열리고 첫 탭에는 `claude agents` 관제 화면이, 둘째 탭에는 지금처럼 대화할 PM이 뜬다. research-1·research-2·synth는 화면 없이 background에서 돈다. 10분 뒤 토스트가 "research-2: 2024년 이전 자료도 포함할까요?"처럼 역할 이름과 마지막 질문을 함께 띄운다. cmux의 출발점이 Claude의 "입력을 기다립니다" 알림에 맥락이 없다는 불만이었으니, 알림에는 반드시 역할과 질문이 들어가야 한다 ([cmux README](https://github.com/manaflow-ai/cmux)). 짧은 답이면 관제 탭에서 Space로 엿보고 한 줄로 답한다. 길게 이야기할 일이면 `hx pop research-2`로 파란 탭을 연다. agent view에서 Enter를 누르면 관제 화면이 그 세션으로 바뀌지만, `hx pop`은 관제 탭을 그대로 둔 채 대상만 새 탭으로 연다. 이것이 1st-party와의 정확한 차이다. 대화를 마치고 `←`로 떼면 research-2는 계속 일하고, 하네스는 그사이 사용자가 입력한 문장을 원장에 남긴다. research-2는 standing order에 따라 바뀐 범위를 `@synth`와 `@pm`에 알린다. 종합 단계에서 synth는 각 역할의 report.md와 원장을 함께 읽고, 주장마다 measured/inferred/guessed 라벨을 붙여 낸다. 사용자는 최종 답만이 아니라 `hx show research-1`로 중간 산출물을 언제든 연다. "마지막 결과만 읽힌다"는 불만은 팝아웃이 아니라 이 파일 규약이 먼저 해결한다.

`hx ls`의 상태 어휘는 데이터 원천인 `claude agents --json`을 따르고, 정렬은 Grok 대시보드처럼 입력 대기를 맨 위로 올린다. OpenAI의 Need input/Working/Ready, xAI의 Working/Idle/Awaiting, Claude의 Working/Needs input/Idle/Completed가 같은 어휘라 사용자가 새로 배울 것이 없다 ([proflead](https://proflead.dev/posts/openai-codex-agents-dashboard-codex-queue/), [Agent Dashboard](https://x.ai/news/agent-dashboard), [agent view](https://code.claude.com/docs/en/agent-view)).

직접 대화를 허용하는 순간 생기는 정합성 문제는 OpenAI와 Anthropic의 이슈 트래커가 이미 목록을 만들어 뒀다. 메시지가 누구에게 가는지 항상 보여야 하고, 바쁜 에이전트에게는 인터럽트할지 큐에 넣을지 고를 수 있어야 하며, 사람과 나눈 대화는 부모에게 요약으로 돌아가야 하고, 기록은 나중에 읽을 수 있어야 한다 ([#34377](https://github.com/openai/codex/issues/34377), [#33885](https://github.com/openai/codex/issues/33885)). 탭 제목과 Claude의 `Message @name…` 입력창이 대상을 보여 준다. Claude는 작업 중인 background 세션에 보낸 답장을 인터럽트 없이 큐에 넣고, 서브에이전트 transcript에서는 Ctrl+Enter로 대기 중인 작업이 끝나기 전에 메시지를 읽게 할 수 있다 ([agent view](https://code.claude.com/docs/en/agent-view), [sub-agents](https://code.claude.com/docs/en/sub-agents)). 사용자가 서브에이전트에 직접 말해도 오케스트레이터가 모르는 문제와, DM을 받은 서브에이전트가 자신을 team-lead로 밝히며 부모 이력을 노출한 문제는 역할을 별도 세션으로 띄우면 구조적으로 줄어든다 ([#72591](https://github.com/anthropics/claude-code/issues/72591), [#55488](https://github.com/anthropics/claude-code/issues/55488)). 각 역할은 자기 transcript 안에서 PM의 메시지와 사람의 입력을 시간순으로 처리하므로, Codex V2가 피하려던 "부모 명령과 사용자 입력의 동시성" 문제가 한 세션 안의 메시지 순서 문제로 바뀐다. 남는 문제는 PM이 사람의 변경을 모른 채 상충하는 지시를 보내는 경우인데, 원장 알림이 이것을 잡는다.

### 5-4. MVP 범위: 터미널이 아니라 원장을 만든다

| 단계 | 넣는 것 | 넣지 않는 것 | 완료 기준(제안) |
|---|---|---|---|
| Phase 0: 이번 주, 개인용 | 역할 프롬프트를 `.claude/agents/<role>.md`로 옮기기, PATH 스크립트 `hx-up`·`hx-ls`·`hx-pop`·`hx-down`, `crew` 창과 관제 탭, Notification 훅 토스트, WT `bellStyle` | 데몬, MCP, Codex 연동 | E1~E8 통과, 일주일 실사용에서 팝아웃 마찰 기록 |
| MVP | `hx` CLI와 로컬 데몬, team.yaml, 레지스트리, http 훅 수신, 토스트 헬퍼, report.md 규약과 근거 라벨, 곁대화 원장, `send`(PM 경유·메일박스·Codex queue), `fork`, `adopt`, Codex hand-off 멤버, 동시 실행 상한과 역할별 사용량 표시, `/pop` 슬래시 명령 | 자체 터미널 앱, Codex live attach, psmux 백엔드, 모바일·원격, GUI 대시보드, 클라우드 실행 | 팝아웃이 명령 1개로 3초 안에 끝남, 곁대화가 원장에 빠짐없이 남고 종합 결과에 반영됨, 입력 대기 알림의 누락·오탐을 측정해 공개, 하네스 때문에 생기는 IME 회귀 0 |
| Phase 2 | Codex app-server `--remote` live attach, channel 기반 push 전송, psmux 파워 모드, Zellij 백엔드 검토 | — | E10~E16 통과 시 |
| Phase 3 | OSC 7501·9;4를 해석하는 자체 호스트, MSIX 패키지와 `Windows.UI.Shell.Tasks` 작업 표시줄 연동, 원격·모바일 조종 | — | 시장 반응 확인 후 |

Phase 0은 PowerShell로 충분하다. MVP 데몬은 TypeScript를 권한다. Claude Agent SDK(TS 0.3.310), Codex SDK(`@openai/codex-sdk` 0.164.0), ACP SDK(`@agentclientprotocol/sdk` 2.0.2)가 모두 npm 패키지로 나와 있어 벤더 표면을 한 언어로 다룰 수 있다 ([Claude Agent SDK npm](https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk), [Codex npm](https://www.npmjs.com/package/@openai/codex), [ACP SDK npm](https://www.npmjs.com/package/@agentclientprotocol/sdk)). 다만 Agent SDK를 구독 OAuth로 태우는 구성은 정책 리스크가 있으므로(5-6), 구독 경로는 수정하지 않은 `claude` 바이너리를 띄우는 방식으로 한정한다. 이 판단의 핵심은 "자체 터미널을 미룬다"에 있다. 한국어 IME 버그는 주로 Claude Code의 Ink TUI 쪽에서 생겨 호스트를 새로 만들어도 고쳐지지 않고, 호스트가 주는 고유 가치(OSC 상태 신호 해석, 패키지 앱 전용 작업 표시줄 연동)는 Phase 3에서도 늦지 않다 ([#16322](https://github.com/anthropics/claude-code/issues/16322)).

### 5-5. 경쟁 제품과의 차별점

| 경쟁 대안 | 그들의 설계 | 이 설계가 다른 점 |
|---|---|---|
| cmux | macOS 터미널 자체를 교체하고, 팀원은 spawn 시점의 tmux shim으로만 분할하며, 상태는 화면·OSC 신호에 의존 | Windows Terminal 위에 얹고, 사후 팝아웃하며, 상태는 `claude agents --json`과 벤더 훅에서 읽음 |
| wmux · Herdr · psmux | 새 터미널이나 멀티플렉서를 채택해야 하고, 지속성은 그 서버가 쥠 | 터미널은 그대로, 지속성은 벤더 supervisor가 쥠 |
| Runner · OpenRig · Maestro · Orchestrator.inc | 크루·좌석 개념은 가깝지만 OpenRig는 WSL2 전용, Runner는 알파, GUI는 자체 채팅창 | 벤더 네이티브 TUI에 그대로 붙고 Windows 네이티브 |
| VS Code Agents window · Warp · Devin Desktop | 자기 앱 안에 탭·분할을 그리고, Codex는 2등급이거나 크레딧 과금 | OS 터미널 탭, 사용자의 기존 Claude·Codex 구독 그대로, 두 벤더 동급 |
| Claude agent view | attach가 현재 터미널을 점유하고 새 탭 열기가 없으며, 서브에이전트는 행으로 보이지 않음 | 관제 탭을 유지한 채 대상만 새 탭, 곁대화 원장 |
| Codex agents · subagents | V2 자식은 읽기 전용이고, 스레드를 새 터미널에서 여는 명령이 없음 | 역할을 최상위 세션으로 두고 queue로 전송, 팝아웃은 resume |

가격 측면의 차이도 크다. 상용 제품의 불만은 사용량 미터링에 몰려 있는데, 사용자가 이미 가진 Claude Code·Codex 구독으로 CLI를 그대로 띄우는 하네스에는 추가 미터링 계층이 없다 ([Visual Studio Magazine](https://visualstudiomagazine.com/articles/2026/06/04/copilot-billing-shock-hits-developers.aspx), [Antigravity 포럼](https://discuss.ai.google.dev/t/complaint-regarding-the-current-antigravity-quota-system/146600)).

## 6. 설계를 굳히기 전에 이 PC에서 돌려 볼 실험 19가지

P0은 Phase 0 전에, P1은 MVP 전에, P2는 MVP와 함께 확인한다. 노트의 근거는 모두 문서와 이슈이고, 이 PC에서 조합 동작을 재현한 것은 없다.

| ID | 우선 | 확인할 것 | 방법 | 결과가 바꾸는 설계 |
|---|---|---|---|---|
| E1 | P0 | background 세션과 WT 탭 attach 왕복 | `claude --bg -n t1 "..."` 뒤 레시피 C로 새 탭에서 attach, 대화, `←`로 떼고 `claude agents --json`에서 계속 실행 확인 | 코어 경로 성립 여부 |
| E2 | P0 | 두 탭이 같은 세션에 동시 attach | E1 상태에서 다른 탭으로 한 번 더 attach | `hx pop`을 두 번 쳤을 때 기존 탭 재사용 규칙 |
| E3 | P0 | `--bg`와 `--agent`·`--settings`·`--mcp-config` 조합 | 조합해 spawn한 뒤 훅과 MCP 도구가 동작하는지 확인 | `hx up`이 역할 설정을 주입하는 방법 |

## 결론

이번 조사로 바뀐 이해는 팝아웃이 기능이 아니라 구조의 결과라는 점이다. 역할을 처음부터 세션으로 띄우면 팝아웃은 `wt` 한 줄로 내려앉고, 그 한 줄은 Anthropic이 #24123이나 #24384를 받아들이는 순간 누구나 갖게 된다. 오래 남을 가치는 반대편, 벤더들이 일부러 피한 영역에 있다. OpenAI는 "자식을 지휘하는 건 부모뿐"이라는 불변식을 지키려고 V2 자식을 읽기 전용으로 만들었고, Symphony 팀은 실행 중 스티어링을 포기했으며, Anthropic에서는 "사용자가 서브에이전트에 직접 말해도 오케스트레이터가 모른다"는 이슈가 stale로 닫혔다. 사용자의 제품은 정반대에 건다. 사람의 개입을 버그가 아니라 1급 이벤트로 다루고, 기록하고, 관련 역할과 종합 에이전트에 전달한다. 실무자들이 한 자릿수 세션에서 멈춘다는 사실은 이 제품이 에이전트 수를 늘리는 도구가 아니라 사람의 주의를 배분하는 도구여야 한다는 뜻이기도 하다.

당장 할 일은 역할 프롬프트를 `.claude/agents/<role>.md`로 옮기고, 이름 붙은 background 세션과 관제 탭과 `hx-pop` 스크립트로 일주일을 써 보며 E1~E8을 확인하는 것이다. 지켜볼 신호는 세 가지다. Anthropic이 Windows Terminal 백엔드나 "/fork를 새 탭으로"를 내놓으면 탭 열기의 가치는 사라지고 원장·혼합 벤더·주의 라우팅만 남는다. Codex가 #33885를 풀면 Codex 멤버도 Claude와 같은 수준으로 직접 대화할 수 있게 된다. 그리고 Lauren Tan식 재브리핑 승격은 벤더의 내부 포맷이 바뀌어도 살아남는 유일한 승격 방식이므로, 서브에이전트 transcript를 직접 여는 실험(E13)이 실패하더라도 `hx adopt`의 기본 구현으로 둘 가치가 있다.
