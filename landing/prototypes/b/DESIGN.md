# Experii 랜딩 시안 B · 디자인 명세

## 1. 콘셉트와 기억에 남는 순간

이 시안은 **“대화가 면접에서 꺼낼 수 있는 물건이 된다”**를 한 페이지의 중심 장면으로 삼는다. Apple에서 제품 화면 자체를 넓은 무대의 주인공으로 두는 법, OpenAI에서 입력과 생성 결과를 서로 다른 형태로 보여 주는 법을 가져왔다. 전체는 순백·옅은 회색·큰 산세리프와 넉넉한 여백으로 조용하게 유지하고, 단계색은 기능의 상태를 설명할 때만 쓴다.

기억에 남는 순간은 섹션 4의 21초짜리 사용자 시작 시퀀스다. 방문자가 재생을 누르면 학습 대화가 현장 과제로 바뀌고, `LEFT JOIN · IS NULL`이 경험 카드로 이동한 뒤, 날짜가 10월 27일·11월 2일·11월 25일로 넘어간다. 마지막에는 처음 저장한 카드가 다시 열리고 `다시 본 날` 점 세 개가 찬다. 자동 시작하거나 반복하지 않으며, 직접 빈칸을 풀고 알림을 넘기는 조작도 같은 무대에 남겨 둔다.

## 2. 토큰

### 색

대비 값은 각 색을 흰 배경의 본문색으로 썼을 때의 WCAG 명암비다. 검정 섹션에서는 흰색 또는 별도 검증한 밝은 회색만 쓴다.

| 색 | 역할 | 흰 배경 대비 |
|---|---|---:|
| `#18181a` | 기본 글자·주 CTA | 17.73:1 |
| `#68686f` | 보조 본문 | 5.53:1 |
| `#f4f4f6` | 제품 무대·입력 배경 | 짙은 글자 사용 |
| `#3d5a99` | 학습 대화 | 6.73:1 |
| `#2f6f5e` | 현장 과제 | 5.91:1 |
| `#9a5b13` | 경험 카드 | 5.41:1 |
| `#74448c` | 리마인드 | 7.12:1 |
| `#ffffff` | 페이지·폰 화면 | 기본 배경 |

TSD의 크림색 임시 배경 대신 `#ffffff`와 `#f4f4f6`을 썼다. 시안 A와 시각적으로 분리하고, Apple의 제품 촬영 무대처럼 콘텐츠의 외곽과 타이포가 또렷하게 보이게 하기 위해서다. 단계색 세 개는 의미를 그대로 유지했고, 리마인드는 다른 단계와 쉽게 구별되는 보라색으로 정했다.

### 글자 크기

글꼴은 외부 리소스 하나인 Pretendard Variable만 쓴다.

| 역할 | 360px | 1440px | 행간·굵기 |
|---|---:|---:|---|
| 히어로 | 40–56px | 최대 92px | 1.06 / 760 |
| 섹션 제목 | 40px | 최대 76px | 1.06 / 740 |
| 큰 질문 섹션 | 46px | 최대 88px | 1.06 / 740 |
| 리드 본문 | 19px | 최대 28px | 1.45 / 400–720 |
| 본문 | 16px | 16px | 1.65 / 400 |
| 목업 본문 | 11–13px | 11–13px | 1.52–1.60 / 400–750 |

제목은 `text-wrap: balance`, 전체 한글은 `word-break: keep-all`을 적용한다. 일반 본문의 폭은 약 740px 이내로 제한한다.

### 간격과 모서리

- 섹션 상하 간격: 360px에서 92px, 데스크톱에서 96–184px 유동값
- 본문 셸: 데스크톱 최대 1180px, 모바일 좌우 14px
- 기본 간격 단위: 8px, 큰 단락은 24·48·72px 계열
- 작은 조작: 12px, 콘텐츠 카드: 18–22px, 큰 무대: 28–52px
- 모든 실제 조작의 최소 높이: 44px
- 그림자는 폰 한 대와 메모 더미에만 제한하고 카드 묶음에는 반복하지 않는다

## 4. 인터랙션 명세

| 요소 | 시작 조건 | 움직임·상태 변화 | 시간·곡선 | 동작 줄이기 | JS 없음 | 참고와 변경점 |
|---|---|---|---|---|---|---|
| 히어로 질문 칩 | 클릭 | 해당 SQLD 세트로 폰 문구·SQL·카드·알림을 바꾸고 섹션 4로 이동 | 스크롤만 브라우저 기본 | 즉시 이동 | 완성된 JOIN 질문이 보임 | OpenAI 입력창+칩을 실제 입력이 아닌 대본 선택기로 바꿈 |

반복적인 섹션 진입 효과와 장식용 스크롤 애니메이션은 두지 않았다. 움직이는 속성은 `transform`과 `opacity`뿐이며, 버튼 색 변화는 직접 조작에 대한 피드백이다.

## 5. 섹션 4 루프 조작 방식과 근거

TSD 6.2와 같은 **탭 4개 + 폰 한 대**를 기본으로 썼다. 탭은 `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`, roving `tabindex`를 사용하며 좌우 화살표로 이동한다. 모바일에서도 네 탭을 한 줄에 유지하되 글자와 번호를 간결하게 줄였다.

브리프 4.3의 `처음부터 이어 보기`를 탭에 추가했다. 방문자가 재생을 눌렀을 때만 약 21초 대본이 진행되고, 재생 중에는 일시정지, 멈춘 뒤에는 계속, 마지막에는 다시 보기로 바뀐다. 직접 조작할 때는 재생 타이머를 취소해 상태 충돌을 막는다.

Apple식 sticky 무대는 사용하지 않았다. 따라서 TSD와 구조 차이가 없고, 카카오톡 인앱에서 주소창 높이가 바뀔 때 고정 구간이 튀거나 키보드가 장면을 덮는 문제가 없다. 높이는 `100svh`와 `100dvh`를 함께 쓰고, 폰 내부만 제한 높이에서 스크롤한다. 동작 줄이기에서는 이동 애니메이션을 제거하고, JS가 없으면 S0~S13이 포함된 네 패널이 한 폰 안에서 세로로 모두 보인다.

## 7. 자기 점검

### frontend-design 스킬의 흔한 티 대조

1. 따뜻한 크림·점토색 조합: 사용하지 않았다. 흰색·회색 무대에 의미색만 배치했다.
2. 모든 제목 위 대문자 라벨: 사용하지 않았다. 라벨은 예시·기능 상태처럼 정보가 있을 때만 썼다.
3. 동일한 둥근 카드 묶음: 문제는 선으로 나눈 발화, 차별점은 타임라인, 시작은 번호 목록으로 구조를 달리했다.
4. 장식 그라데이션과 반복 그림자: 알림 잠금화면의 공간 구분 외에는 장식 그라데이션을 쓰지 않았고, 그림자는 폰과 메모 더미에만 썼다.
5. 섹션마다 같은 등장 효과: 두지 않았다. 움직임은 루프가 닫히는 한 장면과 직접 조작 피드백에만 썼다.

### 검사 결과

- 지정된 9개 금지 문자열: `index.html` 부분 문자열 검색 0건
- 파일 크기: 약 75KB로 200KB 제한 이내
- S0~S13, 정확한 JOIN SQL, 날짜 10월 27일 화요일·11월 2일 월요일·11월 25일 수요일 포함
- 탭 좌우 화살표, 두 빈칸 보기, 알림 넘기기, 재생·일시정지·계속·다시 보기 핸들러 연결
- 360px CSS: 셸 좌우 14px, 모든 그리드 단일 열 전환, 폰 폭 유동, `pre` 내부 스크롤, 선택지 한 열, 페이지 `overflow-x: hidden`
- 브라우저 렌더 시도: 로컬 Chrome과 Edge가 현재 실행 권한에서 렌더 프로세스를 시작하지 못해 이미지 검증은 완료하지 못했다. 대신 스크립트 구문, ID/ARIA 연결, 이벤트 대상, 반응형 CSS를 코드 수준에서 검사했다.
