## 0. 한눈에

1. **헤드라인은 변화 하나만 말한다.** "자격증 있어요"가 "이런 과제에서 이렇게 써 봤어요"로 바뀌는 장면이다. 구독 연결이나 0원 같은 진입 장벽 이야기는 섹션 6의 짧은 띠로 미룬다. PRD 9장과 Aside의 배치(카드 1장 + 가격표 1줄)가 같은 판단이다.
2. **루프는 폰 한 대 안에서 끝까지 보여 준다.** SQLD JOIN 질문 하나가 현장 과제, 경험 카드, 1·7·30일 알림을 거쳐 30일 알림을 누르면 처음 만든 카드가 다시 열리는 데서 끝난다(3장 대본). 아이콘 4개짜리 원형 다이어그램은 쓰지 않는다.
3. **"GPT 연동 학습 화면"은 미리 써 둔 대화로 그린다.** 사용자는 GPT와 공부하는 Experii 화면을 원했다. TSD 1.2는 연동 실연을 범위에서 뺐다(H4 `[확인필요]`). 그래서 화면은 GPT와 공부하는 모습으로 그리되, 입력창 칩은 `내 GPT · 연결 준비 중`으로 두고 "예시 화면·미리 써 둔 대화"라고 밝힌다(3.7). 실제 LLM 호출은 열린 결정으로 남긴다(6장).
4. **설명 방식 기본안은 탭 스테퍼(TSD `LoopStepper`)다.** 여기에 방문자가 직접 누르는 "처음부터 이어 보기" 재생을 더한다. 자동 재생 시연(Aside)과 스티키 스크롤(TIO·토스)은 장단점을 4장에 정리했다.
5. **신뢰는 숫자가 아니라 구체성에서 나온다.** 사용자 수, 후기, 로고 월, 성과 수치가 없다. 그 자리를 실제 SQLD 범위의 문제, 문법이 맞는 SQL, 날짜와 출처가 찍힌 카드, 정확한 알림 날짜로 채운다.
6. **금지 표현은 5장 표를 따른다.** 문구 검사(`content-guard`)는 부분 문자열로 찾는다. 그래서 "최고 기록", "1위 상품", "100% 완료"처럼 데모 속 UI 문구에 섞여 들어가도 CI가 실패한다.

## 1. USP 한 문장과 증명 장면

### 1.1 USP 한 문장

**내부용 (PRD 5장 압축)**

> 취업 준비 대학생이 SQLD를 공부하는 날마다, Experii는 그날 AI와 나눈 대화로 현장 과제를 내고, 푼 결과를 면접 답변 한 줄로 저장해 1·7·30일에 다시 꺼내 준다. 그래서 면접에서 "자격증 있어요" 대신 "이런 과제에서 이렇게 써 봤어요"라고 말하게 된다.

**랜딩용 `[초안]`** (금지 표현과 H4 예정형을 통과한 형태)

> 공부한 날마다 현장 과제 하나, 면접 답변 한 줄. 1·7·30일 뒤에 다시 꺼내 드려요.

- PRD USP 원문에 있는 "이미 쓰는 GPT·Claude를 추가 비용 없이"는 헤드라인에서 뺀다. 이유는 둘이다. H4가 `[확인필요]`이고, PRD 9장이 무료를 USP가 아니라 진입 장벽 제거 수단으로 정했다. 이 내용은 섹션 6에서 예정형으로만 쓴다.
- PRD 원문의 "1년 치 내 경험"은 랜딩에서 "몇 달 치"(PRD 10장 섹션 5 표현)로 쓴다. 꾸준히 써야 쌓인다는 전제(PRD 5장 리텐션)를 숨기지 않는다.

**움직임 규칙** (리서치 03 5장, TSD 12장)

- 애니메이션 라이브러리를 쓰지 않는다. CSS transition·keyframes와 IntersectionObserver 하나로 만든다.
- 움직이는 속성은 `transform`·`opacity`만 쓴다. `box-shadow`·`filter`·`backdrop-filter`는 애니메이션하지 않는다.
- 화면에 들어올 때 **한 번만** 실행한다. Aside 아이콘 벽처럼 들어올 때마다 다시 재생하지 않는다.
- 등장 애니메이션은 모두 `@media (prefers-reduced-motion: no-preference)` 안에 둔다. 동작 줄이기 설정이면 꺼 버리는 대신 **완성 상태를 바로** 보여 준다(Readwise).
- 등장 곡선과 시간은 Aside 수치를 기본으로 쓴다. 위에서 10px 내려오며 투명도 0→1, 0.32초, `cubic-bezier(0.22, 1, 0.36, 1)`, 항목 간격 0.35초.
- CSS 스크롤 연동 애니메이션(`animation-timeline`)은 `@supports` 안에서만 쓴다. 2026-10-26 기준 Firefox 정식판(158)이 지원하지 않는다.
- 높이는 `100vh` 대신 `100svh`·`100dvh`를 쓴다(카카오톡 인앱 주소창).

  - 면접관: SQL 써 보셨어요?
  - Before: 자격증 있어요.
  - After: 주문 없는 회원을 찾는 과제에서 LEFT JOIN으로 이렇게 써 봤어요.
  - 출처 칩: 10월 26일 SQLD 대화에서
- 입력창 플레이스홀더(한 번만 타이핑): LEFT JOIN이랑 INNER JOIN 차이가 헷갈려
- 칩 3개: `JOIN 차이가 헷갈려` · `GROUP BY랑 HAVING` · `ROW_NUMBER랑 RANK`
- 입력창 화살표 버튼 `aria-label`: 이 질문으로 예시 화면 보기

**구현 메모**

- 입력창은 진짜 `<textarea>`로 만들지 않는다. 글자를 칠 수 있는 것처럼 보이면 혼란스럽다. 입력창 모양의 카드 안에 타이핑 연출(`aria-hidden`)을 두고, 같은 문장을 `sr-only`로 한 번 둔다. 실제로 반응하는 것은 칩과 화살표 버튼뿐이다.
- 플레이스홀더를 계속 돌리지 않는다(openai.com은 몇 초마다 바꾼다). 계속 바뀌는 콘텐츠는 WCAG 2.2.2 대상이다. 한 번 치고 멈춘다.

**피할 것**

- 성과·속도 헤드라인(TIO형 "N분 만에 끝내세요"), 아바타와 "N명 이상" 사회적 증거, 다크 배경의 긴박감 연출
- 히어로 자동 시연. Aside는 832px 고정 높이 시연이 모바일 첫 화면을 다 차지한다. 시연은 섹션 4가 맡는다.
- 입력창 안 모델 이름 칩(예: Aside식 "모델명 · High"). 연동이 이미 된다는 뜻이 된다(3.7).
- 히어로에 AI 회사 로고

### 2.5 섹션 5 · 차별점 (`#difference`)

**목표**: 경쟁사를 말하지 않고 시작 시점이 다르다는 것을 보여 준다. 지원 직전이 아니라 공부하는 날마다 쌓이고, 몇 달 치 기록은 나중에 만들 수 없다.

**가져올 장치** (하나를 주 장치로 고른다 `[선택]`)

| 장치 | 어디서 | Experii에서 | 장점 / 주의 |
|---|---|---|---|
| A. 가로 타임라인 | TSD 6.1 #5 | `자격증 공부 ── 지원 ── 면접` 축 위에 막대 두 개. "지원할 때 쓰는 도구"는 지원 지점부터, Experii는 공부 첫날부터 시작해 카드 점이 찍힌다 | TSD 기본안이고 한눈에 읽힌다. 다른 도구 막대는 이름 없이 회색으로 |
| B. 날짜가 찍힌 카드 더미 | bragdoc "2 days ago / Last 30 days", Cursor 작업 목록 `now / 10m / 30m`, Readwise 마지막 CTA의 히어로 카드 재사용 | 경험 카드가 시간순으로 겹치고 스탬프 `오늘 · 7일 전 · 30일 전 · 3개월 전`. 카드마다 과목·주제·답변 한 줄 | "나중에 거꾸로 만들 수 없다"가 가장 잘 보인다. 카드 수·기간은 예시 표기 |
| C. 같은 달력, 다른 칸 | 취준생에게 익숙한 채용달력 화면(리서치 02 1.2, 자소설닷컴 앱스토어 첫 스크린샷) | 같은 월 달력인데 칸에 회사 마감 대신 공부한 날의 카드 점과 주제(`9/3 SELECT`, `9/17 GROUP BY`, `10/26 JOIN`) | 대비가 강하다. 다만 경쟁사 화면을 떠올리게 하는 것이 목적이라 비교로 읽힐 수 있다. 달력 디자인을 베끼지 않는다 |

**카피 재료 `[초안]`**

- 눈썹 라벨: `언제 시작하나요`
- 제목: 지원할 때가 아니라, 공부하는 날마다
- 본문: **몇 달 치 기록은 나중에 한꺼번에 만들 수 없어요.** 공부한 그날 남긴 카드에는 날짜와 내가 쓴 쿼리, 푼 과제가 그대로 있어요.
- 보조: 면접 날짜가 정해지기 전부터, 공부한 날마다 한 칸씩.
- 보완 문장(리서치 02 패턴 D): 지원할 때 쓰는 도구와 같이 써도 돼요. Experii는 그 전 몇 달을 맡아요.
- 전제를 숨기지 않는 문장(PRD 5장 리텐션): 꾸준히 공부한 만큼 쌓여요.
- 카드 더미 예시 문구(모두 `예시` 표기)

### 3.3 SQL 정답·오답·검증

모두 SQLite 3.50.4에서 3.1 예시 데이터로 실행해 확인했다. 문법은 Oracle·SQL Server·PostgreSQL·MySQL 공통으로 썼다.

**정답 (S7)**

```sql
SELECT m.member_id, m.member_name, m.joined_at
FROM members m
LEFT JOIN orders o
  ON m.member_id = o.member_id
WHERE o.order_id IS NULL;
```

결과: `(2, 서준, 2026-09-10)`, `(4, 도윤, 2026-10-12)`

| 확인한 경우 | 결과 | 화면에서 쓰는 곳 |
|---|---|---|
| `LEFT JOIN`을 `INNER JOIN`으로 바꿈 | 0행 | S7 오답 피드백 |
| `o.order_id IS NULL`을 `WHERE`가 아니라 `ON`에 넣음 (`ON m.member_id = o.member_id AND o.order_id IS NULL`) | 회원 4명이 모두 나옴 | S11 7일 뒤 알림 "주의할 점" |
| 같은 결과를 `NOT EXISTS`로 | 서준·도윤 2행 (정답과 같음) | S12 30일 뒤 꼬리질문 |

```sql
SELECT m.member_id, m.member_name, m.joined_at
FROM members m
WHERE NOT EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.member_id = m.member_id
);
```

### 3.4 경험 카드 전문

| 칸 | 문구 |
|---|---|
| 머리 | 경험 카드 · 2026.10.26 (월) |
| 면접 질문 | SQL을 써 본 적 있나요? |
| **내 답변 한 줄** | 쇼핑몰 회원·주문 데이터에서 한 번도 주문하지 않은 회원을 LEFT JOIN과 IS NULL로 추려, 첫 구매 쿠폰 대상 목록을 만드는 과제를 풀어 봤습니다. |
| 배운 점 | LEFT JOIN은 왼쪽 테이블 행을 모두 남기고, 짝이 없으면 NULL로 채운다. |
| 내가 쓴 쿼리 (접힘) | 3.3 정답 SQL |
| 태그 | `SQLD` `2과목` `JOIN` |
| 출처 칩 | 출처 · 10월 26일 SQLD 대화 |
| 다시 볼 날 | ○ 10월 27일 · ○ 11월 2일 · ○ 11월 25일 (S13에서 ● 3개) |

- 카드에 세션에 없던 성과 수치를 넣지 않는다(TSD 6.2). "쿠폰 사용률이 올랐다" 같은 결과를 지어내지 않는다. 쿼리 결과 행 수(2명)도 실적처럼 보일 수 있어 카드에는 넣지 않는다.
- **답변 한 줄에는 "과제"라는 말을 꼭 남긴다.** "실무에서", "회사에서", "프로젝트를 진행해" 같은 경력 표현으로 바꾸지 않는다. 연습 과제를 실제 업무처럼 말하게 만들면 면접에서 사용자에게 해가 된다. PRD 1장의 After도 "이런 과제에서 이렇게 써 봤어요"다.
- 히어로 After 말풍선(TSD 6.1, 해요체)과 이 카드의 답변 한 줄(합니다체)은 같은 내용의 말투 차이다. 디자인 에이전트는 둘을 같은 색(대화색 → 카드색 체인)으로 묶는다.

### 3.6 칩 대체 세트 B·C

히어로와 S0의 칩을 누르면 ①~④가 이 세트로 바뀐다. 기본 세트는 위의 JOIN(A)이다. 장면 구성은 A와 같고, 바뀌는 문자열만 적는다. SQL은 모두 실행해 확인했다. 디자인 에이전트가 칩을 2개로 줄이면 C를 뺀다.

**세트 B · GROUP BY와 HAVING — 재구매 회원 찾기**

- 칩: `GROUP BY랑 HAVING`
- 사용자: GROUP BY랑 HAVING 차이가 뭐야? WHERE랑 헷갈려
- AI 설명: WHERE는 묶기 전에 행을 하나씩 거르고, HAVING은 GROUP BY로 묶은 다음 그룹을 걸러요. 그래서 COUNT(*) 같은 집계 조건은 HAVING에 써요.
- AI 되묻기: 취소된 주문은 빼고 2번 이상 결제한 회원을 찾으려면, '취소 제외'와 '2번 이상'은 각각 어디에 쓸까요?
- 사용자: 취소 제외는 WHERE, 2번 이상은 HAVING?
- 상태줄: 대화에서 개념 찾기 · WHERE, GROUP BY, HAVING / 상황 고르기 · 쇼핑몰 주문 데이터 / 현장 과제 만들기
- 과제 카드: `현장 과제` · `쇼핑몰 CRM팀 요청 (가상 상황)` — 결제 완료 주문이 2건 이상인 재구매 회원을 뽑아 주세요. 취소된 주문은 세지 않아요.
- 테이블: `orders(order_id, member_id, ordered_at, status)`, status는 `'PAID'` 또는 `'CANCELLED'`
- 예시 데이터: 101(회원 1, PAID) · 102(회원 1, PAID) · 103(회원 3, PAID) · 104(회원 3, CANCELLED) · 105(회원 4, PAID)
- 빈칸: `[ ? ] COUNT(*) >= 2` 자리, 보기 `WHERE` · `HAVING`
- 정답 SQL

  ```sql
  SELECT member_id, COUNT(*) AS paid_orders
  FROM orders
  WHERE status = 'PAID'
  GROUP BY member_id
  HAVING COUNT(*) >= 2;
  ```

  결과: `(1, 2)` 회원 1번 한 명
- 오답 피드백 (`WHERE`를 고름): WHERE에는 COUNT 같은 집계 함수를 쓸 수 없어서 오류가 나요. 묶은 다음 거르는 건 HAVING이에요. (SQLite에서도 집계 함수 오용 오류 확인)
- 덧붙일 수 있는 확인: `WHERE status = 'PAID'`를 빼면 취소 주문까지 세서 회원 3번도 결과에 들어온다(`(1, 2)`, `(3, 2)`로 확인)
- 답변 한 줄: 주문 데이터에서 취소 주문은 WHERE로 빼고, GROUP BY와 HAVING으로 결제 2건 이상인 재구매 회원을 뽑는 과제를 풀어 봤습니다.
- 태그: `SQLD` `2과목` `GROUP BY`
- 알림
  - 1일 뒤 · 배운 점: WHERE는 묶기 전의 행을, HAVING은 묶은 뒤의 그룹을 걸러요. 집계 조건은 HAVING에.
  - 7일 뒤 · 활용 방안: 'n번 이상', '합계 n원 이상'처럼 그룹 단위 조건이 나오면 HAVING이에요. 예: 한 학기에 세 번 이상 결석한 학생 찾기.
  - 30일 뒤 · 면접 예상 질문: "데이터에서 조건에 맞는 고객을 뽑아 본 적 있나요?" 내 답변 한 줄 다시 보기 →

**세트 C · 윈도우 함수 + 인라인 뷰 — 회원별 최근 주문 1건**

- 칩: `ROW_NUMBER랑 RANK` (리서치 03의 세 번째 칩 "서브쿼리는 언제 써?" 대신. 이 세트도 인라인 뷰, 즉 FROM 절 서브쿼리를 쓴다)
- 사용자: ROW_NUMBER랑 RANK 차이가 뭐야?
- AI 설명: 둘 다 순서대로 번호를 매겨요. 값이 같으면 RANK는 같은 순위를 주고 다음 순위를 건너뛰어요(1, 1, 3). ROW_NUMBER는 같아도 1, 2, 3처럼 서로 다른 번호를 줘요.
- AI 되묻기: 회원마다 주문을 딱 1건만 남기고 싶다면 어느 쪽이 안전할까요?
- 사용자: 겹치면 안 되니까 ROW_NUMBER?
- 상태줄: 대화에서 개념 찾기 · ROW_NUMBER, PARTITION BY / 상황 고르기 · 쇼핑몰 주문 데이터 / 현장 과제 만들기
- 과제 카드: `현장 과제` · `고객센터팀 요청 (가상 상황)` — 회원마다 가장 최근 결제 주문 1건만 뽑아 주세요. 같은 날 주문이 두 건인 회원도 있어요.
- 예시 데이터: 세트 B 데이터 + 106(회원 4, PAID, 105와 같은 날)
- 빈칸: 함수 자리, 보기 `ROW_NUMBER()` · `RANK()`
- 정답 SQL

  ```sql
  SELECT member_id, order_id, ordered_at
  FROM (
    SELECT member_id, order_id, ordered_at,
           ROW_NUMBER() OVER (PARTITION BY member_id ORDER BY ordered_at DESC) AS rn
    FROM orders
    WHERE status = 'PAID'
  ) t
  WHERE rn = 1;
  ```

  결과: 회원 1·3·4가 한 건씩
- 오답 피드백 (`RANK()`를 고름): 같은 날 결제한 주문이 두 건이면 RANK는 둘 다 1이라 회원 4번은 2건이 나와요. 회원당 1건이 필요하면 ROW_NUMBER예요. (회원 4번이 2행 나오는 것 확인)
- AI 덧붙임: 윈도우 함수 결과(rn)는 같은 SELECT의 WHERE에서 바로 쓸 수 없어서 FROM 안에 한 번 감쌌어요. (바깥으로 감싸지 않으면 오류 나는 것 확인)
- 답변 한 줄: 주문 데이터에 ROW_NUMBER로 회원별 최신순 번호를 매기고, 인라인 뷰로 1번만 골라 회원별 최근 결제 주문을 뽑는 과제를 풀어 봤습니다.
- 태그: `SQLD` `2과목` `윈도우 함수`
- 알림
  - 1일 뒤 · 배운 점: 값이 같을 때 RANK는 같은 번호, ROW_NUMBER는 다른 번호를 줘요.
  - 7일 뒤 · 활용 방안: '그룹마다 n건만' 뽑을 땐 PARTITION BY + ROW_NUMBER를 인라인 뷰로 감싸요. 예: 학과별 최근 공지 1건.
  - 30일 뒤 · 면접 예상 질문: "중복 데이터를 정리해 본 적 있나요?" 내 답변 한 줄 다시 보기 →
- **주의**: 이 세트를 쓸 때 화면 문구에 "1위"를 쓰지 않는다. `content-guard`가 부분 문자열 "1위"로 실패한다. "1번", "가장 최근"으로 쓴다.

### 3.7 "GPT 연동 학습 화면" 표기 규칙

사용자 요청은 "Experii 화면에서 GPT를 연동해 학습을 돕는 화면"이다. TSD 1.2는 연동 실연을 뺐고, H4는 `[확인필요]`다. 둘을 함께 지키는 표기다.

| 자리 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 입력창 칩 | `내 GPT` + 작은 회색 `연결 준비 중` | 모델 이름·버전·추론 강도 칩, `연결됨` |
| AI 말풍선 이름표 | `AI` | 특정 모델 이름, AI 회사 로고 |
| 폰 바깥 캡션 | 예시 화면이에요. 쓰던 GPT를 연결해 이렇게 공부하도록 준비하고 있어요. 지금 보이는 대화는 미리 써 둔 예시예요. | "실제 GPT 응답", "지금 바로 연결" |

실제 LLM 호출은 기본안에서 뺀다. 비용, 남용·프롬프트 주입, 금지 표현이 섞인 답, 응답 지연(LCP·INP 예산)을 떠안게 되고, 미리 써 둔 문구와 달리 `content-guard`로 검사할 수 없다(리서치 03 5.4). 넣을지는 6장의 열린 결정이다.

### 3.8 JS가 없을 때와 동작 줄이기 설정일 때

- **JS 없음** (TSD 6.2): 4단계가 세로로 모두 보인다. ① 대화 전체(S1~S4) ② 과제 카드 + 빈칸이 채워진 정답 SQL + 결과 2행 ③ 경험 카드(점 0개) ④ 알림 3장을 세로 목록으로. 히어로 입력창에는 첫 질문이 이미 다 쓰여 있다.
- **동작 줄이기**: 타이핑, 페이드, 곡선 이동, 스택 슬라이드를 모두 끄고 각 탭의 **마지막 상태**를 바로 보여 준다. 탭 전환과 빈칸 풀기는 그대로 된다. 이어 보기 버튼을 누르면 장면을 0.6초 간격으로 순간 전환만 한다.
- **첫 렌더**: 서버 HTML에 위의 완성 상태를 넣는다. JS가 붙은 뒤에만 처음 상태로 되돌린다.

### 4.3 권장안: 후보 2를 바탕으로 후보 1의 "이어 보기"를 더한다

- 섹션 4 본문은 **후보 2(탭 스테퍼)**다. TSD 6.2와 맞고, 방문자가 빈칸을 직접 푼다.

  - 이어 보기 중 빈칸은 가짜 탭이 `LEFT JOIN`을 고른다. 끝나면 "직접 풀어 보세요" 안내와 함께 ② 탭으로 돌아갈 수 있게 한다.
- ① 탭의 사용자 말풍선 타이핑만 화면에 다 들어왔을 때 **한 번** 자동으로 실행한다(약 1초, Readwise). 5초 미만이라 멈춤 수단이 필요 없다.

- 디자인 에이전트 둘이 다른 후보를 고를 수 있다. 그때는 위 표의 단점 칸에 대한 대응을 각자 시안에 적는다.

| 면접 준비 끝 | PRD 7장 | "3분이면 면접 준비 끝" | 면접에서 꺼낼 경험이 쌓여요 |
| 합격 보장 | PRD 7장 | — | (쓰지 않음) |
| 확연한 차이 | PRD 7장 | "답변이 확연한 차이" | 답변이 "이렇게 써 봤어요"로 바뀌어요 |
| 최고 | PRD 7장 | "최고 기록", "최고 금액 주문" (SQL 예시 속 문구 포함) | 가장 큰, 가장 최근 |
| 1위 | PRD 7장 | "1위 상품", RANK 설명의 "1위" | 1번, 첫 번째 |
| 유일 | PRD 7장 | "유일하게 공부 단계부터" | 공부하는 날부터 |
| 보장 | TSD `[제안]` | "개인정보 보호를 보장", "기록 보장" | (보안 문구는 TSD 13장 범위만) |
| 무조건 | TSD `[제안]` | "무조건 기억나요" | — |
| 100% | TSD `[제안]` | 진행 바 "100%", "100% 자동" | 진행 바에는 숫자 대신 체크 표시 |

PRD 10장 서브 카피 원안의 "3분이면 준비 끝"은 금지어 "면접 준비 끝"에 걸리지 않지만, "3분"이 측정 전이고 "준비 끝"이 결과를 단정하므로 "3분 안에 시작하도록 만들고 있어요"로 바꾼다(TSD 6.3).

### 5.2 성과·속도를 약속하는 말

| 피할 표현 | 이유 | 대체 |
|---|---|---|
| 끝내세요, 끝, 1트, 합격까지 | 성과 보장(PRD 7장), 경쟁사 히어로 문법 | 쌓여요, 남아요, 써 봤어요 |
| N분 만에, 10초 만에 | 근거 없는 속도 약속 | 제품 사실 숫자만: 1·7·30일, SQLD 2과목 |
| 면접에서 확실히 달라져요 | H2 `[가설]` | "자격증 있어요" 대신 "이렇게 써 봤어요" |
| 기억이 n% 오래가요, 망각 곡선 수치 | 효과를 수치로 주장 | 1·7·30일에 다시 꺼내 줘요 |
| 무엇이든, 무제한, 한계 없이 | 무제한 뉘앙스(Aside식) | SQLD 한 과목, 루프 4단계로 좁혀 말한다 |

### 5.3 비교·비하

| 피할 표현 | 이유 | 대체 |
|---|---|---|
| 경쟁사 실명(TIO, 자소설닷컴 등) | TSD 1.2·6.1 | 지원할 때 쓰는 도구 |
| ○○와 달리, 다른 앱은 마감 직전에야 | 깎아내리는 비교(PRD 7장) | 면접 날짜가 정해지기 전부터 |
| 벼락치기 대신 | 사용자 행동 비하 | 공부한 그날 바로 남긴 기록 |
| 범용 AI에는 없는, ChatGPT로는 안 되는 | 연결해 쓰는 GPT·Claude를 깎아내림 | 쓰던 GPT·Claude 그대로, 공부가 경험으로 남게 |
| 가장 똑똑한, SOTA, #1, 벤치마크 막대 | 최상급·비교(Aside식) | 실제 같은 예시 화면 |
| 지금의 ○○는 고장 났다 | 카테고리 비난 | 질문형(섹션 3) |
| 빛나는 한 줄 | 다른 서비스 카피와 겹침 | 면접 답변 한 줄 |

### 5.4 근거 없는 사회적 증거

- 사용자 수, "N명이 신청", 아바타 묶음: 실제 값이 생기기 전까지 쓰지 않는다.
- 후기, 별점, 합격 기업 로고 월, 마스킹한 이메일 후기: PRD 5장 "후기 근거 없음".
- YC 같은 배지, 언론 로고: 없다.
- 고객 인용은 PRD 3장 원문만, 출처는 "창업자와 주변 대학생 2명"으로 사실대로. "많은 대학생이"로 일반화하지 않는다.

### 5.5 H4 `[확인필요]`: 연동·비용

| 피할 표현 | 대체 (TSD 6.3) |
|---|---|
| 이미 쓰는 GPT·Claude를 연결하세요 / 연결돼요 | 연결할 수 있게 준비하고 있어요 |
| 추가 비용 없음, 0원 (조건 없이) | Experii 이용료는 받지 않아요. AI는 쓰고 있는 구독을 그대로 써요. |
| 3분이면 끝 | 3분 안에 시작하도록 만들고 있어요 (또는 숫자 생략) |
| ChatGPT 대화를 가져와요, 지난 대화를 정리해 줘요 | Experii 안에서 공부한 대화가 카드가 돼요 |
| 무제한으로, 마음껏 | (구독 사용 한도를 같이 쓴다. 쓰지 않음) |
| `연결됨 ✓` 상태 화면 (배지 없이) | `예시 화면` 배지 + `준비 중` 칩 |
| 모델 이름·버전 칩 | `내 GPT · 연결 준비 중` |
| OpenAI·Anthropic 로고, "공식", "제휴", "파트너" | 글자 "GPT·Claude" |
| 1·7·30일 리마인드를 지금 되는 기능처럼 | 예시 배지 + `출시 예정 기능` |
| 이력서·면접 답변 자동 작성(F6)을 지금 되는 기능처럼 | 언급하면 `출시 예정` |

### 5.6 보안·데이터 주장

- "기기에만 저장", "암호화", "AI 회사와 공유하지 않아요", "절대 유출되지 않아요": PRD에 데이터 처리 방식이 없다. 구독을 쓰는 구조라면 대화는 AI 회사로 가는 것이 기본이다. 처리 방식이 정해지기 전에는 TSD 13장·`/privacy` 범위만 쓴다.
- 저장 신뢰는 경쟁 앱 불만의 핵심(리서치 02 #2)이라 약속하고 싶어지지만, 지킬 방법이 정해지기 전에는 문구로 약속하지 않는다.

### 5.7 압박·긴박감·유행어

- D-day, 오늘마감, 마감 임박, 선착순: "귀찮지 않은" 톤과 충돌. SQLD 시험일(2026-11-14 제63회, 2차 자료)을 끌어와 카운트다운을 만들지 않는다.
- 연속 기록(streak), 리그, 순위, "오늘 안 하면 기록이 끊겨요": PRD에 없는 기능이고 2026년에 비판받는 패턴이다(리서치 03 2.3).
- 갓생 같은 유행어, 이모지 남발.

### 5.8 사례 속 정직성

- 경험 카드 답변은 "과제를 풀어 봤습니다"로 쓴다. "실무에서 ~했습니다", "회사 프로젝트에서" 같은 경력 표현으로 바꾸지 않는다(3.4).
- 과제 카드에는 `(가상 상황)`을 붙인다.
- 카드에 세션에 없던 성과 수치를 넣지 않는다(TSD 6.2).
- 폰 안의 장식 버튼이 진짜로 눌리는 것처럼 보이지 않게 한다. 반응하는 것은 칩, 빈칸 보기, 탭, 알림 넘기기, 재생 버튼뿐이다.
