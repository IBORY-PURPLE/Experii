## 1. 한 줄 정의

AI와 공부·작업한 세션의 **대화 원문을 로컬에 쌓고**, 그 위에 **한 번 더 요약정리**해서, 나중에 면접에서 쓸 수 있는 **경험 기록**이 실제로 만들어지는지 창업자 본인이 검증한다.

명령 한 번(`Experii해줘`)으로 두 계층이 돈다.

- **1계층 — 캡처(Capture)**: SpecStory가 하듯 현재 세션의 대화 원문을 로컬 `.md`로 보존한다.
- **2계층 — 정제(Distill)**: 그 원문을 다시 읽어 "경험 카드"(면접용 구조화 요약)로 요약정리한다.

## 2. 이 문서의 위치

이미 완성된 전체 MVP 기획([../PRD_MVP_V1.md](../PRD_MVP_V1.md), [../TSD_MVP_V1.md](../TSD_MVP_V1.md))은 웹 + MCP 서버 + Supabase를 갖춘 풀스택 제품이다. Pre-MVP는 그 큰 제품을 짓기 **전에**, 가장 핵심인 가설 하나만 로컬에서 싸게 검증한다.

| | 전체 MVP (기존 기획, 보존) | Pre-MVP (이 문서) |
|---|---|---|
| 구조 | 웹 + MCP + Supabase 풀스택 | 로컬 Claude Code Skill만 |
| 데이터 | 원문 안 받음, 요약만 서버 저장 | 원문도 로컬 캡처 + 그 위에 요약정리 |
| 묶는 단위 | 학습 ID 필수(`SQLD-1`) | 날짜 + 도메인 태그 (ID는 선택) |
| 사용자 | 창업자 → 테스터 5~10명 | 창업자 본인(도그푸딩)만 |
| 운영비 | Vercel + Supabase | 0 (전부 로컬 파일) |
| 검증하는 것 | 기록 성공률·요약 수정률·열람 | **요약정리가 면접에 쓸 만한가** |

전체 MVP의 설계 철학("요약은 사용자의 AI가, 원문은 서버에 안 보냄")은 Pre-MVP에서도 **상위 호환**된다. Pre-MVP는 로컬이라 원문을 로컬에 둘 수 있고, 나중에 MCP로 보낼 때는 **요약본만** 보내면 기존 철학과 그대로 맞는다.

## 3. 왜 Pre-MVP인가

전체 MVP는 "요약이 쌓이면 가치가 있다"를 전제로 웹·MCP·DB를 먼저 짓는다. 그런데 가장 근본적인 미지수는 그 앞에 있다.

> **원문을 쌓고 한 번 더 요약정리하면, 정말로 "면접에서 꺼내 쓸 만한" 경험 기록이 나오는가?**

이게 안 되면 웹도 MCP도 의미가 없다. 그래서 Pre-MVP는 인프라를 0으로 두고 이 질문에만 답한다. 검증 주체는 창업자 본인이며, 재료는 본인의 실제 학습·작업 세션(SQLD 공부, 리서치, 코딩 등)이다.

## 4. 핵심 가설과 판단 기준

| # | 가설 | 측정 | 통과 기준(제안) |
|---|---|---|---|
| H1 | 명령 한 번으로 세션 원문이 안정적으로 캡처된다 | `Experii해줘` 실행 중 원문 `.md`가 정상 생성된 비율 | 95% 이상 |
| H2 | 원문을 2계층으로 정제하면 면접에 쓸 만한 경험 카드가 나온다 | 생성된 경험 카드 중 **창업자가 "면접에서 실제로 쓰겠다"**고 판단한 비율 | 60% 이상 |
| H3 | 쌓인 경험 카드를 다시 꺼내 볼 가치가 있다 | 2주 뒤 카드를 다시 열어 면접 답변 준비에 쓴 경험 | 1회 이상, 정성 기록 |

- **H2가 핵심 지표다.** 미달하면 요약 포맷·프롬프트를 고쳐 다시 잰다. 그래도 안 되면 제품 방향을 재검토한다.
- H1이 미달하면 캡처 방식(세션 transcript 읽기 vs 현재 컨텍스트 직접 요약)을 바꾼다.
- 설계 제약: 기록에 드는 사용자 행동은 **명령 하나**(`Experii해줘`)를 넘지 않는다.

## 5. 사용자

| 단계 | 사용자 | 클라이언트 |
|---|---|---|
| Pre-MVP | 창업자 본인 | Claude Code (로컬) |
| 범위 밖 | 테스터, 웹/Desktop 사용자 | 전체 MVP에서 다룸 |

## 6. 핵심 시나리오

1. **공부/작업**: 평소처럼 Claude Code에서 SQLD를 공부하거나 리서치·코딩을 한다.
2. **정리 명령**: 마칠 때 `Experii해줘`라고 입력한다. (학습 주제를 함께 말해도 된다: "Experii해줘 — SQLD 서브쿼리")
3. **캡처**: Skill이 현재 세션의 대화 원문을 로컬 `~/.experii/raw/`에 `.md`로 저장한다.
4. **정제**: 저장한 원문을 다시 읽어 "경험 카드"를 만들고 `~/.experii/cards/`에 저장한다. 카드에는 도메인·태그·한 줄 요약·면접 한 마디·STAR·배운 개념·막힌 점이 들어간다.
5. **확인**: Skill이 카드 내용을 화면에 보여 주고 저장 경로를 알려 준다.
6. **평가(검증)**: 창업자가 카드를 읽고 "이거 면접에서 쓸 만한가?"를 판단해 H2 데이터를 쌓는다. 틀린 부분은 직접 `.md`를 고친다.
7. **되돌아보기**: 며칠 뒤 `~/.experii/cards/`를 열어 그동안의 경험 카드를 훑는다.

## 7. 범위

### 7.1 포함 (Pre-MVP)

- `Experii해줘` 트리거 (Claude Code Skill)
- 1계층: 현재 세션 대화 원문을 로컬 `.md`로 캡처
- 2계층: 원문 → 경험 카드(면접용 구조화 요약) 생성
- 경험 카드를 로컬에 저장하고 화면에 보여 줌
- 날짜·도메인·태그 기반 로컬 저장소 레이아웃
- 코어 로직(정제·포맷·저장)을 모듈로 분리 → 다음 단계 MCP에서 재사용

### 7.2 제외 (전체 MVP 또는 그 이후)

| 제외 | 이유 |
|---|---|
| 웹 UI, 타임라인 화면 | 전체 MVP. 로컬 `.md` 열람으로 대체 |
| MCP 서버, 서버 조합·callback | 2단계. Pre-MVP는 설계 여지만 남김(12장) |
| Supabase, 계정, OAuth, 매직 링크 | 전체 MVP |
| 학습 ID 자동 채번(`SQLD-1-S3`) | 날짜+태그로 대체. 필요하면 수동 태그 |
| 세션 종료 훅으로 분모 측정 | 전체 MVP의 H1 측정용. Pre-MVP는 명령 실행 성공률만 |
| 민감정보 서버 업로드 차단 로직 | 로컬이라 서버 전송이 없음. 단, 카드에 비밀값이 섞이지 않도록 정제 단계에서 주의(10장) |
| 다중 사용자, 공유 | 창업자 도그푸딩이 먼저 |

### 7.3 여지만 남겨 둘 것

- 경험 카드에 `학습 ID`(예: `SQLD-1`)를 **선택 필드**로 받는다. 저장만 하고, 조합·채번은 나중에 MCP가 한다 — 전체 MVP의 ID 체계와 이어진다.
- 경험 카드를 JSON으로도 함께 저장(프런트매터 + 본문)해서, 나중에 MCP가 기계적으로 읽어 조합할 수 있게 한다.

## 8. 2계층 구조 (Capture → Distill)

```
  Claude Code 세션 (SQLD 공부 / 리서치 / 코딩)
                     │  Experii해줘
                     ▼
  ┌─────────────────────────────────────┐
  │ 1계층 · Capture (SpecStory식)         │
  │   현재 세션 대화 원문 → .md 저장        │
  │   ~/.experii/raw/2026-10-23-...md     │
  └──────────────────┬──────────────────┘
                     ▼
  ┌─────────────────────────────────────┐
  │ 2계층 · Distill (경험 요약정리)         │
  │   원문 읽기 → 도메인·태그·STAR·면접 한마디│
  │   ~/.experii/cards/2026-10-23-...md   │
  │   (+ .json 사본)                      │
  └──────────────────┬──────────────────┘
                     ▼
         화면 출력 + 창업자 평가(H2)
                     ┆
                     ┆ (범위 밖, 다음 단계)
                     ▼
     MCP 서버가 카드들을 조합 → 유저 callback
```

## 9. 기능 요구사항

우선순위: P0 = Pre-MVP 필수, P1 = 하면 좋음(검증 품질↑), P2 = 다음 단계

| ID | 요구사항 | 우선 | 인수 기준 |
|---|---|---|---|
| FR-01 | `Experii해줘` 트리거 (Skill) | P0 | 자연어 "Experii해줘" 또는 `/experii`로 전체 흐름이 한 번에 실행된다 |
| FR-02 | 1계층: 현재 세션 원문 캡처 | P0 | 현재 대화 원문이 `~/.experii/raw/`에 `.md`로 저장된다. 저장 경로를 사용자에게 알린다 |
| FR-03 | 2계층: 경험 카드 생성 | P0 | 원문을 바탕으로 도메인·태그·한 줄 요약·면접 한 마디·STAR·배운 개념·막힌 점을 채운 카드가 생성된다 |
| FR-04 | 경험 카드 저장 | P0 | 카드가 `~/.experii/cards/`에 `.md`로 저장되고, 기계 판독용 `.json` 사본도 함께 저장된다 |
| FR-05 | 카드 화면 출력 | P0 | 생성 직후 카드 핵심을 화면에 보여 주고 저장 경로를 안내한다 |
| FR-06 | 주제·태그 수동 지정 | P1 | "Experii해줘 — SQLD 서브쿼리"처럼 말하면 도메인/태그에 반영된다 |
| FR-07 | 비밀값 섞임 방지 | P1 | 카드 본문에 API 키·개인키·주민등록번호 형식이 감지되면 마스킹하고 사용자에게 알린다 |
| FR-08 | 학습 ID 선택 필드 | P1 | "SQLD-1로" 같이 말하면 카드에 `learning_id`로 기록한다(채번·조합은 안 함) |
| FR-09 | 카드 목록 보기 | P2 | `Experii 목록`으로 그동안의 카드를 날짜·도메인별로 요약해 보여 준다 |
| FR-10 | 세션 transcript 자동 탐색 | P2 | 현재 컨텍스트가 압축돼 원문이 희미하면 Claude Code 세션 로그(JSONL)에서 원문을 보강한다 |

## 10. 경험 카드 포맷 (면접용)

```markdown
---
id: 2026-10-23-sqld-subquery
date: 2026-10-23
domain: 데이터베이스
tags: [SQLD, 서브쿼리, 쿼리최적화]
learning_id: null          # 선택. 전체 MVP의 SQLD-1 체계로 이어짐
duration_estimate: 2h
source: claude-code
---

## SQLD 서브쿼리 학습

**한 줄 요약**: 상관·인라인·스칼라 서브쿼리 3유형을 직접 쿼리로 작성하며 차이를 익힘

**면접 한 마디**: "SQLD 준비 중 서브쿼리 유형별 동작과 최적화 포인트를 쿼리 작성으로 학습했습니다."

**STAR**
- S(상황): SQLD 자격증 준비, 서브쿼리 단원
- T(과제): 세 유형의 차이와 쓰임을 구분해 설명할 수 있어야 함
- A(행동): 각 유형을 예제 쿼리로 작성하고 실행 계획을 비교
- R(결과): 유형 선택 기준을 한 문장으로 정리, 오답 3개 교정

**배운 개념**: 상관 서브쿼리의 행별 평가, 인라인 뷰, 스칼라 서브쿼리 성능 주의점

**막힌 점 / 다음 할 일**: 상관 서브쿼리 성능 튜닝은 아직 약함 → 다음 세션에서 EXISTS 변환 연습
```

- 면접 활용성을 최우선으로, "한 줄 요약 / 면접 한 마디 / STAR"를 고정 골격으로 둔다.
- `.json` 사본은 같은 데이터를 키-값으로 담아, 다음 단계 MCP가 조합할 때 바로 읽는다.

## 11. 성공 지표 (창업자 도그푸딩)

- **주 측정**: 생성한 경험 카드 수, 그중 "면접에서 쓰겠다" 비율(H2).
- **보조**: 캡처 성공률(H1), 카드를 다시 열어 본 횟수(H3), 사용자가 카드를 직접 고친 정도(요약 품질의 역지표).
- 2주 운영 후 H2가 60% 이상이면 전체 MVP(웹+MCP)로 전진, 미달이면 포맷·프롬프트를 고쳐 재측정.

## 12. 다음 단계로의 연결 (범위 밖, 설계 여지)

Pre-MVP가 검증에 성공하면, 로컬에 쌓인 경험 카드(`.json`)를 재료로 다음을 연다.

1. **MCP 서버화**: Pre-MVP의 코어 로직(정제·포맷·저장)을 MCP 도구로 래핑 → Claude Desktop 등에서도 `Experii해줘`가 동작.
2. **조합 + callback**: MCP 서버가 여러 카드를 도메인·기간별로 **조합**해, "이 사람의 데이터베이스 경험" 같은 상위 요약을 만들어 유저에게 돌려준다(callback).
3. **전체 MVP 합류**: 학습 ID 체계·웹 타임라인([../PRD_MVP_V1.md](../PRD_MVP_V1.md))과 데이터 모델을 맞춰 통합.

이 때문에 Pre-MVP는 코어 로직을 처음부터 **UI·트리거와 분리**하고, 카드를 `.json`으로도 저장한다([tsd.md](tsd.md) 참조).

## 13. 용어

| 용어 | 뜻 |
|---|---|
| 캡처(Capture) | 현재 세션의 대화 원문을 로컬 `.md`로 보존하는 1계층 |
| 정제(Distill) | 원문을 면접용 경험 카드로 요약정리하는 2계층 |
| 경험 카드 | 한 세션의 구조화 요약. `.md` + `.json` 한 쌍으로 저장 |
| 도메인 | 경험의 분야. 예: 데이터베이스, AI 리서치, 프런트엔드 |
| 코어 로직 | 트리거·UI와 분리된 정제·포맷·저장 모듈. 다음 단계 MCP가 재사용 |

## 14. 열린 결정

| # | 질문 | 메모 |
|---|---|---|
| D1 | 원문 캡처를 "현재 컨텍스트 직접 요약"으로 할지, "세션 transcript(JSONL) 읽기"로 할지 | 전자가 단순, 후자가 정확. [tsd.md](tsd.md) 6장에서 비교 — **(확인 필요)** |
| D2 | 저장소 위치를 `~/.experii/`로 할지 프로젝트별로 둘지 | 기본은 홈. 프로젝트별 경험은 태그로 구분 |
| D3 | 경험 카드 언어 (한국어 고정 vs 세션 언어 따라감) | 면접 대비니 기본 한국어 |
| D4 | H2 평가를 어떻게 기록할지 (카드에 `useful: true/false` 필드) | 창업자 자가 평가를 카드에 남겨 추적 |
